01

왜 만들었나

시작은 요구사항 문서가 아니라 한 문단이었다.

자주 쓰는 슬라이드 생성 스킬을 만들까 하고 있어. 그 스킬 안에 PPTX에서 할 수 있는 거는 전부 넣을 수 있게 하고 싶어. 그리고 사람들이 평소에 pptx에서 불편하게 느끼는 부분들을 개선한 단일 html 파일을 만드는 스킬을 만들고 싶은데 어떨까

「아이디어 빌딩」 메모, 2026-08-27 — 이 프로젝트의 첫 문장

가장 불편한 것부터 짚었다. 폰트가 깨지는 자리는 늘 남의 컴퓨터다. 내 화면에서 멀쩡하던 자료가 발표장 노트북에서 무너지고, 그 자리에서는 고칠 방법이 없다.

PPTX로 만들면

폰트를 파일에 심어도 뷰어·OS에 따라 대체된다. 줄이 밀리고 글상자가 넘친다. 고칠 수 있는 건 내 컴퓨터에서뿐이라 현장에서는 손을 못 쓴다.

HTML 한 장으로 만들면

폰트를 CSS에 직접 걸어 두면 브라우저가 그대로 받아 그린다. 화면 크기에 맞춰 통째로 축소되므로 해상도가 달라져도 배치는 그대로다.

그런데 문제를 풀다 보니 진짜 어려운 것은 폰트가 아니었다. 슬라이드는 만들 때마다 색·여백·위계를 새로 판단해야 하고, 그 판단이 매번 조금씩 흔들린다. 그래서 방향을 틀었다. 규칙을 문서로 적어 두는 것에서 멈추지 않고, 규칙을 지켰는지 기계가 검사하게 만드는 쪽으로.

02

이 스킬이 하는 일

발표 대본이나 보고서를 넣으면, 브라우저에서 바로 열리는 HTML 파일 하나가 나온다.

  • 파일 하나로 끝난다

    폰트·이미지·스크립트가 전부 한 파일 안에 들어간다. 첨부도 링크도 없고, 받은 사람은 더블클릭만 하면 된다. 1920×1080 고정 무대가 화면 크기에 맞춰 통째로 축소된다.

  • 슬라이드 유형 15종을 미리 만들어 뒀다

    표지 · 목차 · 좌우 2단(기본) · 소제목 · 인용구 · 큰 수치 · 개념 한 문장 · 사진 1장 · 축 없는 차트 · 카드 그리드 · 비교표 · 단계 · 정리 리스트 · 강조 콜아웃 · 마무리. 2단이 기본이고, 1단은 네 가지 예외일 때만 쓴다.

  • 브라우저에서 그대로 고친다 E

    글자 수정, 색 교체, 슬라이드 복제·삭제·순서 바꾸기, 사진 넣기와 자유 배치, 형광펜·굵게, 투명도, 되돌리기 60단계. 발표 기능과 분리돼 있어 편집기를 지워도 발표는 그대로 된다.

  • 차트 숫자를 고치면 막대 길이가 따라 움직인다

    축도 그리드도 없는 차트라 청중은 오직 길이로 값을 읽는다. 손으로 고치다 데이터를 왜곡하는 일이 구조적으로 막힌다.

  • 색을 손으로 고르지 않는다

    브랜드 색 세 개를 넣으면 팔레트 스크립트가 글자색·차트 강조색을 대비 계산으로 만들어 준다. 브랜드 색을 모르면 색을 지어내지 않고 무채색으로 만든다.

  • 출처를 빼먹으면 통과하지 못한다

    인용문·각주·사진이 있는데 출처가 없으면 자동 검사가 잡는다. 각주 번호를 달았는데 짝이 되는 출처가 없어도 잡힌다.

  • 발표와 인쇄가 같은 파일에서 나온다

    → 한 단계씩 공개 · F 전체화면 · P 16:9 용지로 PDF 저장 · 오른쪽 아래 목차 드롭다운으로 점프.

스킬 안에 들어 있는 파일

assets/
├── template.html    슬라이드 엔진 + 13장 예시 (여기서 시작한다)
├── style-guide.md   색·타이포·라운드·로고·사진·차트 규칙 원본
├── palette.mjs      브랜드 색 3개 → 색 토큰 생성 (대비 자동 계산, 의존성 없음)
├── check.mjs        자동 검사 7종 + 전체 스크린샷 (playwright)
└── review-prompt.md 기계가 못 잡는 것을 서브에이전트에게 보게 하는 프롬프트

RULES.md            규칙·명령 전체를 사람이 읽기 좋게 정리한 참조서
SKILL.md            AI가 읽고 따르는 작업 절차

03

언제 쓰고, 언제 쓰지 않나

스킬은 아무 때나 켜지면 방해가 된다. 켜질 자리를 좁게 적어 뒀다.

이럴 때 쓴다

  • 제안서 · 회사소개 · 영업덱 · 주간보고 같은 대외 발표 자료
  • 화면에 띄우거나 화면 공유로 보여줄 자료
  • 받는 사람의 기기·OS를 모를 때
  • 보고서 · 기획안 · 발표 대본이 이미 있고, 그걸 슬라이드로 옮길 때
  • 발표 직전까지 본인이 직접 고쳐야 할 때

이럴 때는 쓰지 않는다

  • 진짜 .pptx 파일 자체가 필요할 때 → pptx 스킬
  • A4로 인쇄할 문서일 때 → 문서 스킬
  • 애니메이션 · 영상이 필요할 때 → 지원하지 않는다 (모션은 페이드인 하나뿐)
  • 수업·강의처럼 코드 하이라이팅과 실습 화면이 필요할 때 → 수업용 슬라이드 스킬

이렇게 말하면 켜진다

  • 발표 슬라이드 만들어줘
  • 제안서를 슬라이드로
  • 영업덱 만들어줘
  • 주간보고 슬라이드
  • 회사소개 자료
  • html 슬라이드로 만들어줘
  • 화면 공유해서 보여줄 슬라이드

04

규칙 하나에 검사 하나

이 스킬의 전부다. 왼쪽이 정해 둔 규칙, 오른쪽이 그 규칙을 지켰는지 보는 기계 검사다.

  • 01

    내용이 넘치면 글자를 줄이는 게 아니라 슬라이드를 나눈다

    1080px를 넘친 내용은 화면 공유에서 그냥 잘려 나간다. 옮긴 글자 상자와 자유 사진 때문에 네 방향을 다 본다

    overflow
  • 02

    본문 4.5:1, 큰 글자 3:1 — WCAG 명도 대비 기준

    투명도를 쓰거나 rgba()로 적은 색도 배경에 섞인 실제 색으로 환산해 검사한다

    contrast
  • 03

    차트 막대는 배경과도, 서로끼리도 3:1 이상

    색이 달라도 밝기가 같으면 같은 막대가 된다. 브랜드 색을 그대로 쓴 막대가 여기서 걸렸다 (1.83:1 → 3.08:1)

    graphics
  • 04

    이미지가 15% 넘게 잘리면 안 된다

    사진 상자는 넘치지 않으므로 넘침 검사에 안 걸린다. 스크린샷·도표를 넣으면 내용이 조용히 사라진다

    cropped
  • 05

    막대 길이는 값에 비례해야 한다 (오차 5% 미만)

    축도 그리드도 없는 차트라 청중은 오직 길이로 값을 읽는다. 비례가 틀리면 데이터를 왜곡하는 것이다

    barScale
  • 06

    남의 것을 가져다 썼으면 예외 없이 출처를 적는다

    인용문·각주·사진이 있는데 출처가 없으면 통과하지 못한다. 각주 번호와 출처 번호의 짝까지 맞춰 본다

    citations
  • 07

    마크업이 깨지면 내보내지 않는다

    브라우저 콘솔 오류를 그대로 받아 온다

    errors

만들고 나면 이 화면을 본다 — 일곱 개가 모두 빈 배열이어야 내보낸다

$ node assets/check.mjs /절대경로/deck.html /출력폴더

errors: []
overflow: []
contrast(글자 대비 미달): []
graphics(막대 대비 미달): []
cropped(이미지 잘림): []
barScale(막대 비례 어긋남): []
citations(출처 누락): []

그런데 자동 검사는 절반만 잡는다

이 스킬을 만들며 나온 결함들은 대부분 자동 검사를 전부 통과한 상태였다.

  • 강조 글자가 본문보다 흐려 위계가 뒤집힌 것 → 대비 검사는 통과 (읽히기는 하니까)
  • 사진 33%가 잘려 나간 것 → 넘침 검사는 통과 (요소는 안 넘쳤으니까)
  • 차트 막대가 값에 비례하지 않은 것 → 눈으로도 거의 안 보임
  • 소제목이 "파랑·노랑 막대"라는데 화면은 회색·검정이던 것 → 기계는 글과 그림을 대조하지 못한다

그래서 검증을 두 겹으로 만들었다. 자동 검사를 통과시킨 뒤, 전체 스크린샷을 AI 서브에이전트에게 한 장씩 보여 시각 위계·여백·의미 전달을 검토받는다. "높음" 항목을 고치고 나면 다시 캡처해서 한 번 더 받는다 — 한 번에 다 안 잡힌다.

05

이 스킬로 만든 발표 자료

스킬을 설명하는 발표 자료를, 그 스킬로 만들었다. 아래에서 바로 넘겨 볼 수 있다.

발표 중 조작

  • → Space 다음 단계 → 다음 슬라이드
  • ← 이전
  • F 전체화면
  • P 인쇄 → PDF 저장 (16:9 용지)
  • E 편집 모드 켜기 / 끄기
  • 오른쪽 아래 ▦ 버튼 — 슬라이드 목록 드롭다운

PDF로 저장할 때는 인쇄 창에서 「배경 그래픽」을 켜야 배경 사진과 색면이 함께 나옵니다.

덱의 구성 — 13분

  1. 1왜 PPTX를 안 쓰나 3분
  2. 2무엇을 자동화했나 6분
  3. 3만드는 순서 4분

표지 → 목차 → 본론(2단 기본 + 예외 4유형) → 마무리. 스킬이 정해 둔 뼈대를 그대로 따랐습니다.

07

아직 못 고친 것 13가지

코드를 직접 훑고 브라우저에서 돌려 보며 정리했다. 사용자가 겪은 증상이 아니라 만든 사람이 먼저 찾아낸 것이라, 실제로 불편하지 않은 항목은 건너뛰어도 된다.

먼저 고칠 순서

  1. 저장 안 하고 닫기 — 유일하게 "한 일이 통째로 없어지는" 문제다
  2. 스냅샷에서 사진 분리 — 사진을 쓰는 사람에게 되돌리기가 사실상 없다
  3. 비율 고정 + 무대 밖으로 나감 경고 — 둘 다 20줄 안쪽인데 체감이 크다
  4. 표지 그라데이션 방향 — 표지는 가장 많이 손보는 장이다
  5. 나머지는 필요할 때

높음 자료가 망가지거나 잃어버릴 수 있는 것 3건

01저장을 잊으면 편집이 통째로 사라진다

무엇 편집기에는 자동 저장이 없다. 30분을 고쳐도 HTML로 저장을 누르지 않고 탭을 닫으면 전부 사라진다. 브라우저가 "정말 나가시겠습니까?"를 묻지도 않는다.

왜 이 편집기는 발표 직전에 오탈자를 고치는 용도로 자주 쓰인다. 그 상황에서 실수로 탭을 닫는 일이 잦다. 되돌리기 60단계를 공들여 만들어 놓고 정작 이탈 방지는 없는 것은 앞뒤가 안 맞는다.

고침 두 겹으로 막는다. - beforeunload 에 "저장하지 않은 편집이 있습니다" 를 붙인다. 편집을 한 번이라도 했을 때(undoStack.length > 0)만 뜨게 한다. - 30초마다 localStorage 에 현재 무대를 넣어 두고, 파일을 다시 열었을 때 "지난번에 저장 안 한 편집이 있습니다. 되살릴까요?" 를 묻는다. 사진이 든 덱은 용량이 커서 localStorage 5MB 를 넘길 수 있으니, 넘치면 조용히 건너뛰고 beforeunload 만 남긴다.

품 작음(30줄 안팎). 이건 먼저 하는 게 좋다.

02사진을 넣을수록 파일이 무거워지고, 되돌리기가 그 무게를 몇 배로 늘린다

무엇 사진은 가로 1600px·품질 0.82 로 줄여 base64 로 심는다. 한 장에 40~120KB 다. 10장에 사진 8개면 파일이 1MB 를 넘는다. 그런데 되돌리기 스냅샷은 무대 전체 HTML 을 통째로 복사하므로, 사진이 든 덱에서는 스냅샷 하나가 곧 파일 하나만큼 무겁다. 지금은 총 24MB·60단계에서 끊고 있어 터지지는 않지만, 사진이 많으면 되돌리기가 3~4단계밖에 안 남는다.

왜 사진을 많이 쓰는 사람일수록 되돌리기가 필요한데, 정확히 그 사람에게서 되돌리기가 가장 짧아진다.

고침 사진 데이터를 스냅샷에서 빼낸다. img.src 가 data: 로 시작하면 그 문자열을 별도 표에 한 번만 담고 스냅샷에는 열쇠(#img7)만 남긴다. 되돌릴 때 열쇠를 다시 데이터로 바꿔 끼운다. 스냅샷 크기가 수십 KB 로 떨어져 60단계가 사진과 무관해진다. 품 중간(50~80줄). 스냅샷·복원 두 곳만 손대면 된다.

03자유 사진과 글자 상자를 무대 밖으로 밀 수 있는데, 화면에서는 경고가 없다

무엇 자유 사진을 끌어 무대 오른쪽 밖으로 보내면 #stage 의 overflow:hidden 이 잘라 버린다. 화면에서는 그냥 사라진 것처럼 보인다. check.mjs 는 이제 네 방향을 다 보므로 잡지만(방금 고쳤다), 그건 파일을 저장하고 검사를 돌려야 알 수 있다.

왜 편집 중에 바로 알려 주지 않으면, 사라진 사진을 찾느라 헤매거나 사라진 줄도 모르고 발표한다.

고침 끌기가 끝날 때 무대 밖으로 나갔는지 보고, 나갔으면 사이드바에 "이 사진의 일부가 화면 밖에 있습니다" 를 띄운다. 아예 무대 안으로 되밀어 넣는 것(clamp)은 의도적으로 반쯤 걸치게 두는 배치를 막으므로 하지 않는 게 낫다. 품 작음(15줄).

중간 자주 걸리지만 자료가 망가지지는 않는 것 5건

04자유 사진 크기를 바꾸면 비율이 깨진다

무엇 손잡이를 끌면 가로·세로가 따로 논다. 사진은 object-fit:cover 라 찌그러지지는 않고 대신 더 많이 잘린다. 4:1 짜리 틀에 3:2 사진을 넣으면 위아래가 크게 날아간다. cropped 검사가 15% 이상 잘리면 잡지만, 역시 저장 후에야 안다.

고침 Shift 를 누르고 끌면 원본 비율을 지키게 한다. 그리고 손잡이 옆에 지금 몇 % 가 잘리는지 작게 띄운다. 기본을 비율 고정으로 하고 Shift 로 푸는 쪽이 더 안전할 수도 있다 — 대부분은 잘리기를 원하지 않는다. 품 작음(20줄).

05글자 상자를 옮기면 뒤에 남는 자리가 그대로다

무엇 상자 옮기기는 transform 이라 원래 자리는 그대로 비어 있다. 제목을 아래로 내리면 위에 제목만 한 빈칸이 남는다.

왜 PPT 를 생각하고 옮기면 결과가 예상과 다르다. 다만 이건 절충의 결과다 — position:absolute 로 바꾸면 레이아웃이 통째로 무너지고, 그 장의 나머지 배치가 다 어긋난다.

고침 두 갈래. - (쉬움) 상자를 처음 옮길 때 "원래 자리는 비워 둡니다. 배치를 통째로 바꾸려면 슬라이드 유형을 바꾸세요" 를 한 번 띄운다. - (제대로) 자유 배치 토글을 만들어, 켜면 그 장의 모든 글자 상자를 현재 위치 그대로 absolute 로 굳힌다. 그다음부터는 PPT 처럼 움직인다. 대신 그 장은 반응형 배치를 포기하는 것이므로, 끄면 되돌아가게 원래 스타일을 기억해 둬야 한다.

품 쉬운 쪽 5줄 / 제대로 하는 쪽 60줄.

06표지 그라데이션의 방향과 폭이 고정이다

무엇 표지 배경 사진은 항상 왼쪽으로 사라진다. 글이 오른쪽에 있는 표지를 만들면 사진이 글 뒤에서 제일 진하다.

고침 사이드바에 방향 4개(왼쪽·오른쪽·위·아래)와 폭 슬라이더를 둔다. CSS 변수 --fade-dir, --fade-at 로 빼면 마스크 한 줄만 바꾸면 된다. 품 작음(25줄).

07자유 사진을 다른 장으로 옮길 수 없다

무엇 잘라내기·붙여넣기가 없다. 장을 잘못 골라 넣었으면 지우고 파일을 다시 골라야 한다. 검색으로 넣은 사진이면 출처까지 다시 받아야 한다.

고침 고른 자유 사진에 Ctrl+X / Ctrl+V 를 붙인다. 사진 데이터와 위치·크기·자르기·출처 열쇠를 한 덩어리로 들고 다니면 된다. 품 중간(40줄).

08사진 검색이 위키미디어 공용 하나뿐이다

무엇 위키미디어 공용은 백과사전용 사진이 많아 발표 표지에 어울리는 사진이 잘 안 나온다. 사용자가 원래 요청했던 Unsplash 류는 API 열쇠가 필요해서 단일 HTML 파일에 넣을 수 없었다.

고침 현실적인 대안은 두 가지다. (a) 검색어를 영어로 자동 변환해 결과를 늘린다 — 위키미디어는 한글 검색이 특히 약하다. (b) Openverse(열쇠 불필요, CC 전용)를 두 번째 출처로 붙이고 위키미디어와 결과를 섞는다. 예전에 이 컨테이너에서 Openverse 가 403 이었지만, 사용자 브라우저에서는 될 가능성이 높다 — 실패하면 조용히 위키미디어만 쓰게 하면 된다. 품 중간(40줄). (b)는 실제 브라우저에서 확인이 필요하다.

낮음 있으면 좋은 것 5건

09슬라이드 목록에서 제목이 길면 사이드바를 밀어낸다

white-space:normal / overflow:visible 이라 제목이 길면 줄이 늘어난다. text-overflow:ellipsis + nowrap 한 줄이면 끝난다. 품 3줄.

10편집기에 되돌리기 단축키만 있고 나머지가 없다

Ctrl+B(굵게), Ctrl+S(저장), Delete(고른 사진 지우기)가 없다. 사이드바를 매번 눌러야 한다. 품 15줄.

11다크 테마에서 표지·마무리 색이 안 바뀐다

--c-main·--c-sub 는 다크에서 그대로 쓴다. 브랜드 색을 지키려는 의도지만, 아주 밝은 브랜드 색이면 다크 덱에서 표지만 눈부시게 튄다. 다크일 때 채도를 유지한 채 명도만 낮추는 선택지를 주면 된다. 품 20줄.

12인쇄(PDF)에서 자유 사진의 그림자·모서리가 다르게 나온다

@media print 는 편집 표시만 지운다. 배경 그래픽을 끄고 인쇄하면 배경 사진과 막이 통째로 빠져 글자만 남는다. 인쇄 창에서 "배경 그래픽" 을 켜라는 안내가 RULES 에만 있고 화면에는 없다. PDF 저장 버튼 옆에 한 줄로 띄우면 된다. 품 5줄.

13check.mjs 가 저장된 파일만 볼 수 있다

편집 중에는 못 돌린다. 편집기 안에 "지금 검사" 버튼을 넣어 대비·넘침만이라도 브라우저에서 바로 돌리면, 저장→검사→다시 열기 왕복이 사라진다. 대비 계산 함수는 이미 편집기 안에 있다. 품 중간(60줄).

손대지 않는 편이 낫다고 판단한 것

  • 슬라이드를 절대 배치로 바꾸는 것 — PPT와 똑같아지지만, 창 크기가 달라져도 배치가 유지되는 이 도구의 가장 큰 장점을 버리게 된다
  • 되돌리기를 명령 단위(diff)로 바꾸는 것 — 지금은 무대 전체를 찍는 단순한 방식이라 어떤 조작이든 빠짐없이 되돌아간다. diff 방식은 가볍지만 새 기능마다 되돌리기를 같이 만들어야 해서 빠뜨리기 쉽다
  • 자동 검사 항목을 더 늘리는 것 — 지금 7종이면 "확실히 틀린 것"은 거의 덮는다. 더 늘리면 거짓 경보가 늘어 검사를 무시하게 된다
