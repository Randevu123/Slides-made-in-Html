# Slides-in-Html — 규칙 · 명령 전체 정리

정리일 2026-08-27 · 이 문서 하나로 스킬의 모든 규칙과 명령을 볼 수 있다.
`SKILL.md`가 AI에게 주는 작업 지시서라면, 이 문서는 **사람이 읽는 참조서**다.

---

## 0. 한눈에 보기

| 항목 | 값 |
|---|---|
| 스킬 이름 | **Slides-in-Html** (내부 식별자 `slides-in-html`) |
| 만드는 것 | 브라우저에서 바로 열리는 **단일 HTML 파일 하나** |
| 쓰는 자리 | 제안서·회사소개·영업덱·주간보고 등 대외 발표 자료 |
| 화면 규격 | **1920×1080 고정** |
| 기본 폰트 | Pretendard |
| 기본 색 | **무채색** (브랜드 색을 모를 때) |
| 슬라이드 뼈대 | 표지 → 목차 → 본론 → 마무리 |
| 출력 파일명 | `제목, 만든 날짜.html` |
| 검증 | 자동 검사 7종 + AI 시각 검토 |
| 편집 | 브라우저에서 **E 키**로 직접 수정 |

### 왜 PPTX가 아니라 HTML인가

폰트를 CSS에 직접 걸어 두면 어느 기기·브라우저에서 열어도 글자가 안 깨진다. PPTX는 폰트를
파일에 심어도 뷰어·OS에 따라 대체되어 줄이 밀리고 글상자가 넘친다. 화면 크기에 맞춰 통째로
축소되므로 해상도가 달라져도 배치가 그대로다.

### 파일 구성

```
slides-in-html/
├── SKILL.md                  AI에게 주는 작업 지시서
└── assets/
    ├── template.html         슬라이드 엔진 + 13장 예시 (여기서 시작)
    ├── style-guide.md        디자인 규칙 원본
    ├── palette.mjs           브랜드 색 3개 → 색 토큰 블록 생성
    ├── check.mjs             자동 검사 7종 + 전체 스크린샷
    └── review-prompt.md      AI 시각 검토 지시문

RULES.md                      이 문서 — 규칙·명령 전체 참조서
```

편집기는 별도 파일이 아니라 **template.html 안에** 들어 있다(맨 아래 스크립트).
따라서 만들어진 모든 덱에 편집 기능이 함께 딸려 간다.

## 1. 명령어 전부

### 1-1. 색 팔레트 생성 — `palette.mjs`

의존성 없음. node만 있으면 된다.

```bash
# 브랜드 색을 알 때
node assets/palette.mjs "#주조" "#보조" "#강조"
node assets/palette.mjs "#2e6ff2" "#14213d" "#ffb020"

# 브랜드 색을 모를 때 (템플릿 기본값과 동일)
node assets/palette.mjs --neutral

# 사용법 보기
node assets/palette.mjs --help
```

**하는 일**: 색 3개를 받아 `:root`와 `html[data-theme="dark"]`에 붙여넣을 CSS 블록 두 개를
만들고, 항목별 명도 대비 검사표를 함께 출력한다.

**나오는 것**

```
--c-main / --c-sub / --c-accent          입력한 색 그대로 (면에 칠하는 색)
--c-main-tint / --c-sub-tint / --c-accent-tint   옅은 틴트 면
--c-main-text     조용한 라벨용 (eyebrow) — 카드 배경 위 6:1
--c-emph          본문 안 강조용 (굵은 글자·핵심 구절·큰 수치·콜아웃 제목)
--c-main-ondark   목차 오버레이 전용 (항상 어두운 UI, 테마 무관)
--c-chart-hi      차트 강조 막대 — 기본 막대·배경 양쪽과 3:1 이상
--on-main / --on-sub / --on-accent       그 면 위에 얹을 글자색 (흰색 또는 먹색)
```

**주의**: 검사표에 "미달"이 있으면 브랜드 색 자체의 명도를 조정해야 한다는 뜻이다.
주조색과 강조색의 밝기가 비슷하면 차트 강조색이 크게 밀려 원래 인상과 다른 색이 나온다
(예: 파랑 + 노랑 → 강조 막대가 갈색). 이때는 스크립트가 대안 두 가지를 알려 준다.

### 1-2. 자동 검사 — `check.mjs`

```bash
npm install playwright        # 처음 한 번만

# 전체 슬라이드 캡처 + 검사 (시각 검토용 — 이걸 기본으로 쓴다)
node assets/check.mjs /절대경로/deck.html /출력폴더

# 특정 슬라이드만 캡처 (번호는 0부터)
node assets/check.mjs /절대경로/deck.html /출력폴더 0 2 4 7

# 다크 테마로 낼 거면 다크 상태로도 한 번 더
sed 's/<html lang="ko">/<html lang="ko" data-theme="dark">/' deck.html > dark.html
node assets/check.mjs /절대경로/dark.html /출력폴더
```

**출력 예시**

```
slides: 10 | errors: [] | overflow: [] | contrast(글자 대비 미달): []
| graphics(막대 대비 미달): [] | cropped(이미지 잘림): [] | barScale(막대 비례 어긋남): []
| citations(출처 누락): []
```

**전부 `[]` 여야 통과다.**

### 1-3. AI 시각 검토

`assets/review-prompt.md` 의 내용을 그대로 **서브에이전트(Task/Agent 도구)** 에게 맡긴다.
경로 두 곳(`<스킬경로>`, `<스크린샷폴더>`)만 실제 값으로 바꾼다.

## 2. 검증 — 두 겹

**기계가 잡는 것과 눈으로만 잡히는 것은 서로 다르고, 겹치지 않는다.**
실제로 이 스킬을 만들며 나온 결함의 대부분은 자동 검사를 전부 통과한 상태였다.

### 1겹 — 자동 검사 7종

| 항목 | 무엇을 보나 | 어긋나면 |
|---|---|---|
| `errors` | 마크업·스크립트 오류 | 마크업이 깨진 것 |
| `overflow` | 내용이 1080px를 넘쳤나 | 글자를 줄이지 말고 **슬라이드를 나눈다** |
| `contrast` | 글자 ↔ 배경 명도 대비 | 배경색이나 글자색을 조정한다 |
| `graphics` | 차트 막대 ↔ 배경, 막대 ↔ 막대 | `palette.mjs`를 다시 돌려 `--c-chart-hi`를 받는다 |
| `cropped` | 이미지가 잘려 나갔나 (15% 초과) | 그 `.photo-hero`에 `fit`을 붙인다 |
| `barScale` | 막대 길이가 값에 비례하나 (5% 초과) | 막대 높이를 값에 비례하도록 고친다 |
| `citations` | 인용문·각주·사진에 출처가 있나 | `.cite` 또는 `.credit`으로 하단에 출처를 적는다 |

`cropped`와 `barScale`이 왜 따로 있냐면 — 둘 다 **요소가 넘치지 않아서 `overflow`에 안 걸리는데
내용은 사라지거나 왜곡되는** 경우다. 축도 눈금도 없는 차트에서 청중은 오직 막대 길이로 값을
읽으므로, 비례가 틀리면 데이터를 왜곡하는 것이다.

### 2겹 — AI 시각 검토

자동 검사는 "확실히 틀린 것"만 잡는다. 아래는 잡지 못한다.

- **시각 위계**: 가장 중요한 것이 가장 강하게 보이는가 (제목보다 흐린 핵심 수치 등)
- **여백 균형**: 화면에 비해 내용이 휑한가, 한 장만 정렬이 어긋났는가
- **의미 전달**: "주의"가 주의로 보이는가, **글과 그림이 같은 말을 하는가**
- **텍스트 처리**: 줄바꿈에 강조가 쪼개졌는가, 마지막 줄에 두세 글자만 남았는가

절차: 캡처 → 서브에이전트 검토 → "높음" 항목 수정 → **다시 캡처해 재검토**.
한 번에 다 안 잡힌다.

검토가 오탐하지 않도록 **의도된 설계**를 프롬프트에 명시해 둔다 (목차 상단 여백, 무채색, 아이콘 없음).

## 3. 색 규칙

### 3-1. 배분 — 주조 65 : 보조 25 : 강조 10

**면적 비율**이지 채도·명도 규칙이 아니다.

| 토큰 | 쓰는 자리 |
|---|---|
| `--c-main` 주조 65% | 표지·마무리 배경, 표 머리, 배지, 차트 기본 막대 |
| `--c-sub` 보조 25% | 표 첫 칸, 보조 면 |
| `--c-accent` 강조 10% | 주의 콜아웃 — **한 슬라이드에 한 군데, 많아야 두 군데** |

강조색을 여러 번 쓰면 이미 강조가 아니다.

### 3-2. 브랜드 색을 모르면 무채색

**로고가 없거나 브랜드 색을 확인할 수 없으면 색을 지어내지 않는다.** 템플릿 기본값이 이미
무채색이라 아무것도 안 해도 된다. 사용자에게 "무슨 색으로 할까요"를 되묻지 않는다.

| 토큰 | 값 | 역할 |
|---|---|---|
| `--c-main` | `#6f747c` | 중간 회색 — 표지 배경, 차트 기본 막대 |
| `--c-sub` | `#2f3238` | 짙은 차콜 |
| `--c-accent` | `#121417` | 거의 검정 — 강조 |

**무채색에서는 가장 어두운 것이 가장 강하게 읽힌다.** 그래서 강조색이 가장 어둡고, 차트에서
강조하는 막대도 나머지보다 짙다. 반대로 하면(강조를 밝게) 강조가 아니라 후퇴로 읽힌다.

### 3-3. 라벨용 색과 강조용 색을 나눈 이유

`--c-main-text`(라벨)와 `--c-emph`(강조)가 따로 있다.

- 색조가 있는 팔레트에서는 **색 자체가 강조 신호**라 본문보다 옅어도 튀어 보인다.
- 무채색에서는 색조가 없으니 **더 어두운 것만이 강조**로 읽힌다. 라벨용 회색을 강조에 쓰면
  강조가 본문 검정보다 흐려져 위계가 뒤집힌다.

그래서 채도가 거의 없으면(8% 미만) `--c-emph`가 본문색(가장 어두운 값)이 된다.

### 3-4. 라이트 / 다크

고정하지 않는다. `<html data-theme="dark">`를 붙이면 다크, 지우면 라이트.
**다크로 낼 거면 다크 상태로도 검사를 한 번 더 돌린다.** 밝은 테마만 통과하고 다크에서
깨지는 일이 잦다.

### 3-5. 명도 대비 최소 기준 (WCAG)

| 대상 | 기준 |
|---|---|
| 본문 텍스트 | 배경 대비 **4.5:1** 이상 |
| 큰 텍스트 (24px 이상, 또는 18.66px 이상이면서 굵게) | **3:1** 이상 |
| 글자가 아닌 색 덩어리 (차트 막대) | 배경과 3:1, 구분되어야 할 막대끼리도 3:1 |
| 이미지 잘림 | 잘려 나가는 면적 **15% 미만** |
| 막대 비례 | 값 대비 길이 오차 **5% 미만** |

막대 대비를 따로 보는 이유: 글자만 통과시키면 **흑백 인쇄하거나 색약인 사람이 볼 때 막대가
구분되지 않는** 자료가 그대로 나간다. 색상 차이가 아니라 밝기 차이로 구분되어야 한다.

## 4. 타이포 · 형태 규칙

**줄 나눔은 단어(어절) 기준이다.** `.slide`에 `word-break:keep-all`이 걸려 있다.
없으면 한글이 글자 단위로 아무 데서나 잘려 "무엇을 바꿀 것인/가"처럼 끊긴다.
어절 하나가 줄보다 길 때만 `overflow-wrap:break-word`가 마지막 수단으로 자른다. **지우지 말 것.**

### 4-1. 폰트

기본 **Pretendard**. 대안 — 넷 다 오픈소스 라이선스로 무료 상업적 이용 가능
(눈누·각 GitHub 저장소 기준, 실제 배포 전 라이선스 원문 재확인 권장).

| 폰트 | 톤 | 배포처 |
|---|---|---|
| Pretendard (기본) | 중립적 | github.com/orioncactus/pretendard |
| Noto Sans KR | 표준적, 딱딱함 | Google Fonts |
| SUIT | 둥글고 부드러움 | github.com/sun-typeface/SUIT |
| Spoqa Han Sans Neo | 간결·현대적 | github.com/spoqa/spoqa-han-sans |

- **제목 웨이트는 600.** 800·900으로 올리지 않는다.
- **`letter-spacing`은 `normal`.** 한글 사이트에서 흔한 자간 조임을 쓰지 않는다.

### 4-2. 글자 크기 (템플릿에 박힌 값)

| 요소 | 크기 |
|---|---|
| `h1` (표지·목차 대제목) | 96px |
| `h2` (본문 제목) | 56px |
| `.message` (개념 한 문장) | 60px |
| `.quote blockquote` (인용구) | 52px |
| `.bignum .v` (큰 수치) | 96px |
| `.lead` (표지 부제) | 32px |
| `h3` | 32px |
| `p` (본문) | 28px |
| `.shead .sub` (소제목) | 28px |
| `.eyebrow` (라벨) | 22px |
| `.note` | 20px |

### 4-3. 소제목 = 제목 아래 보조 설명문

`.shead .sub`가 이 역할이다. 큰 글자(28px)를 텍스트색 **50% 투명도**로 깔아 제목보다는 작지만
일반 본문보다는 존재감 있게 만든다.

**배경 워터마크가 아니다.** 장식용으로 화면 전체에 깔리는 대형 텍스트 용도로 쓰지 않는다.

### 4-4. 라운드 · 선 · 그림자

- 라운드 **20px**(`--r`), 작은 라운드 **16px**(`--r-sm`)
- **선과 그림자를 쓰지 않는다.** 영역은 `--panel` 배경 면과 라운드로 나눈다
- 카드 테두리가 꼭 필요하면 `2px solid var(--line)`까지만

### 4-5. 전환 모션

**빠른 페이드인 하나뿐** (`.32s ease`, 위로 8px 이동 후 제자리).
슬라이드 전환과 단계 공개(`step-in`) 모두 같은 모션. 다른 트랜지션(슬라이드·줌·회전)을 넣지 않는다.

## 5. 레이아웃 규칙

### 5-1. 화면 규격

**1920×1080(16:9) 고정.** 슬라이드마다 `padding: 96px 120px 84px`. 화면 크기에 맞춰 통째로 scale 된다.

- px 단위를 그대로 쓰고 %·vw·vh로 바꾸지 않는다
- 내용이 넘치면 **글자를 줄이지 말고 슬라이드를 나눈다**

**비율을 지키는 장치 세 가지** — 하나라도 지우면 16:9가 깨진다.

| 장치 | 없으면 |
|---|---|
| `#stage { flex: 0 0 auto }` | 창이 1920px보다 좁을 때 무대가 **가로로 찌그러진다**. flex 아이템의 기본 `flex-shrink:1`이 `width:1920px`을 무시하고 줄인다 |
| `@page { size: 20in 11.25in }` | 브라우저가 무시하고 **Letter/A4로 인쇄**한다. px 단위는 `@page size`에서 안 먹힌다 |
| `fit()`이 `#deck` 크기를 잼 | 편집기 패널이 열렸을 때 무대가 **화면 밖으로 넘친다** |

1920×1080 창에서만 시험하면 이 문제들이 안 보인다. **다른 창 크기에서도 확인한다.**

### 5-2. 좌우 2단이 기본, 1단은 네 가지 예외만

본문은 **좌우 2단**(`.two`)이 기본값이다. 아래 네 유형만 1단을 쓴다.

| 예외 유형 | 클래스 |
|---|---|
| 사진 1장이 주인공 | `.photo-hero` |
| 인용구 | `.quote` |
| 큰 수치 강조 | `.bignums` |
| 개념을 한 문장으로 못박기 | `.message` |

### 5-3. 슬라이드 흐름 뼈대

```
표지 → 목차 → 본론(2단 기본 + 예외 4유형 반복) → 마무리
```

- **표지**: 큰 제목 + 부제 + 발표자/일시
- **목차**: **좌측 위**에 큰 "목차" 타이틀, **우측 아래**에 항목 리스트. `.now`로 현재 위치
- **본론**: 각 장마다 "이 장에서 청중이 가져갈 한 문장"을 먼저 적고 컴포넌트를 고른다
- **마무리**: 인사·Q&A·다음 단계

## 7. 로고 규칙

- 기본 위치 **우측 하단**. `#stage`에 `data-logo="tl|tr|bl|br"`로 4개 모서리 중 선택
- **파일 위치**: 연결된 데스크톱 폴더 안, **작업별 하위 폴더**에 그 작업의 `logo.png`
  (예: `내폴더/2026-분기보고/logo.png`). 스킬 전역 공용 경로를 두지 않는다
- `<img class="logo" src="logo.png">` 상대경로로 넣고 최종 HTML을 같은 폴더에 저장
- **로고가 없으면 그냥 넣지 않는다.** `onerror`로 자동으로 숨겨진다. 로고를 찾느라 작업을
  멈추거나 되묻지 않고, 브랜드 색도 모르는 상황이므로 무채색으로 진행한다
- 표지·마무리에서는 로고에 `filter:brightness(0) invert(1)`이 걸려 **흰색으로 찍힌다.**
  주조색이 밝아 `--on-main`이 먹색으로 잡힌 경우에는 이 규칙을 지우고 원본 로고를 쓴다

## 7-1. 출처 표기 규칙

**논문·통계·기사·인용문·사진 등 남의 것을 가져다 쓰면 예외 없이 슬라이드 하단에 출처를 적는다.**
`check.mjs`의 `citations` 검사가 자동으로 막는다.

| 클래스 | 쓰는 자리 |
|---|---|
| `.cite` | 논문·통계·기사·인용문 출처 (여러 줄 가능) |
| `.credit` | 사진 한 줄 출처 |
| `.credit-mini` | **표지·마무리 사진의 출처를 목차에 모아 적는 아주 작은 줄** |
| `.ref` | 본문에서 인용한 자리에 붙이는 각주 번호 |

```html
<blockquote>인용한 문장입니다.<span class="ref">1</span></blockquote>

<div class="cite">
  <span><b>1</b> 홍길동, 「논문 제목」, 학회지 12(3), 2025, pp.44-58.</span>
</div>
```

- **각주 번호를 달았으면 `.cite`에 같은 번호가 있어야 한다** — 없으면 검사에 걸린다
- 출처에는 **저자 · 제목 · 출처 · 연도**를 적는다. "논문에서" 같은 뭉뚱그린 표기는 출처가 아니다
- 페이지·표 번호가 있으면 함께 적는다
- `.cite`와 `.credit`은 자리가 같다. 사진과 인용이 함께 있으면 `.cite` 하나에 모아 적는다
- 로고가 좌하단이면 출처도 우하단으로 자동 이동한다
- **표지·마무리 사진의 출처는 그 장이 아니라 목차에 적는다.** 표지 좌하단에는 발표자·일시가 있어
  출처와 겹치기 때문이다. 편집기에서 표지에 사진을 넣으면 목차 아래 `.credit-mini`에 13px로
  자동으로 쌓인다. `citations` 검사도 표지·마무리는 목차의 `.credit-mini`를 보고 통과시킨다
- 출처 줄과 사진은 `data-credit-key`로 짝지어져 있다. **사진을 빼거나 그 장을 지우면 짝인 출처
  줄도 같이 사라진다.** 각주가 든 `.cite`에는 열쇠를 걸지 않는다 — 사진을 뺄 때 각주까지
  지워지면 안 되기 때문이다

## 7-2. 사진 넣는 세 가지 방법

| 방법 | 인터넷 | 출처 | 쓰는 자리 |
|---|---|---|---|
| 만들 때 Claude가 넣기 | 필요 | 자동 | 주제에 맞는 사진을 찾아 심는다 |
| 편집기에서 검색 | 필요 | 자동 | E 편집 모드 → 사진 → 단어 검색 |
| 내 파일 끌어다 놓기 | 불필요 | **직접 적어야 함** | E 편집 모드 → 사진 → 끌어다 놓기 |

**자유 사진** — 위치·크기·자르기를 마음대로. 한 장에 여러 개 넣을 수 있다.

| 하는 일 | 방법 |
|---|---|
| 넣기 | 사진 → 자리에서 **자유** 를 고른 뒤 파일을 고르거나 검색 |
| 옮기기 | 사진을 끌면 그 자리로 |
| 크기 | 오른쪽 아래 파란 점을 끌기 |
| 자르기 | **자르기** 버튼을 켠 뒤 사진을 끌면, 틀은 그대로 두고 사진만 움직인다. 틀 밖은 잘린다 |
| 앞뒤 순서 | 사진을 누른 뒤 **앞으로 · 뒤로**. 버튼 옆에 "몇 번째 / 몇 개"가 나온다 |
| 지우기 | 사진을 누른 뒤 **지우기** |

자유 사진의 좌표는 1920×1080 무대 기준 px이라 어느 화면에서 열어도 같은 자리에 놓인다.

**넣는 자리 다섯 가지** — 자동 · 배경 · 왼쪽 · 오른쪽 · 자유. 사진 자리가 없는 장에도 새로 만들어 넣는다.
표지처럼 `.body-main`이 없는 장에서 왼쪽/오른쪽을 고르면 반쪽을 사진이 통째로 채우고
(`.photo-hero.bleed`) 글이 반대쪽으로 밀린다(`.slide.side-left/.side-right`).

| 자리 | 하는 일 |
|---|---|
| 자동 | 표지·마무리면 배경, 사진 자리가 있으면 그 자리, 없으면 오른쪽에 새로 만든다 |
| 배경 | 슬라이드 전체 배경. 글자가 읽히도록 **막이 자동으로 함께 깔린다** |
| 왼쪽 / 오른쪽 | 기존 내용을 반대쪽으로 몰고 그 자리에 사진 칸을 새로 만든다 |

배경 막의 색은 슬라이드에 따라 다르다 — 표지·마무리처럼 글자가 밝으면 어두운 막, 본문처럼
글자가 어두우면 밝은 막. `.foot`·`.credit`·`.logo` 자리는 사진을 깔아도 그대로다.

- 어느 쪽이든 **가로 1600px로 줄이고 압축해 파일 안에 통째로 심는다.** 링크로 걸지 않는다
  (단일 HTML 원칙 — 인터넷 없이도 열려야 한다)
- **표지에 사진을 깔면 어두운 막이 자동으로 함께 깔린다.** 사진 위 글자는 대비를 계산으로
  보장할 수 없어서다. 이 막은 끄지 않는다
- 사진을 받아올 수 없는 환경이면 **억지로 넣지 말고 자리를 비워 둔 채** 사용자에게
  편집기로 직접 넣으라고 알린다. 아무 사진이나 지어 넣지 않는다
- 검색은 위키미디어 공용을 쓴다 — 열쇠(API key)가 필요 없고, 로컬 파일에서도 부를 수 있으며,
  저작자·라이선스를 함께 준다. 넣을 때 그 정보가 `.credit`에 자동으로 들어간다

## 8. 사진 규칙

- **아이콘을 쓰지 않는다.** 개념을 시각화할 때는 아이콘 대신 **사진**을 쓴다
- 보정 없이 **원본 색 그대로**. 듀오톤·흑백 처리 안 함
- 삽입 전 **리사이즈(최대 가로 1600px) + 압축** 후 base64로 심는다
- **출처를 슬라이드 왼쪽 아래에 표기**한다 (`.credit`)
- **로고가 좌측 하단이면 출처는 자동으로 우측 하단으로 이동한다** — 엔진이 `body.credit-flip`을
  붙인다. 직접 클래스를 건드리지 않는다

### 잘림 주의

`.photo-hero`의 기본값은 상자를 꽉 채우려고 **이미지 가장자리를 잘라낸다.**

- 분위기 사진 → 기본값(잘림 허용)
- **스크린샷·도표·글자가 든 이미지 → `.photo-hero fit`** (잘리지 않고 전체가 보인다)

요소 자체는 넘치지 않아 `overflow` 검사에 안 걸리므로 `cropped` 검사가 따로 본다.

## 9. 차트 규칙

- **축 선·그리드라인을 넣지 않는다**
- **막대 위에 숫자를 직접 표기**해 뒷자리에서도 값이 바로 읽히게 한다
- 그래프 제목은 24px / 600
- 기본 막대 `--c-main`, 강조 막대 하나만 **`--c-chart-hi`**
  (`--c-accent`를 그대로 쓰지 않는 이유: 강조색과 주조색의 밝기가 비슷하면 색은 달라도
  흑백으로 보면 같은 막대가 된다)
- **막대 높이는 값에 비례해야 한다.** 가장 큰 값을 80~85%에 두고 나머지를 비율로 맞춘다.
  `barScale` 검사가 5% 넘는 오차를 잡는다

주조색과 강조색의 밝기가 비슷해 `--c-chart-hi`가 어색한 색으로 나오면 둘 중 하나를 고른다.

1. 강조색을 주조색보다 확실히 어둡거나 밝은 색으로 다시 고른다 — 근본 해결
2. 차트에서만 `--c-chart-hi` 대신 `--c-sub`를 쓴다

## 10. 한 단계씩 공개하기

바로 보이면 안 되는 것(리스크, 다음 단계 예고)에 `step-in`을 붙인다.

<div class="callout warn step-in">…</div>

인쇄할 때는 전부 펼쳐져 나온다.

## 11-1. 편집 모드 (E 키)

만든 뒤 브라우저에서 직접 고칠 수 있다. 발표 기능과 분리돼 있어 편집기 코드를 지워도
발표는 그대로 된다.

| 기능 | 방법 |
|---|---|
| 글자 고치기 | 글자를 눌러 바로 입력 |
| **글자 강조** | 끌어서 선택 후 **형광펜 · 굵게 · 지우기**. 지우기는 강조 일부만 선택하거나 커서만 놓아도 통째로 풀린다 |
| **사진 넣기** | 내 파일 끌어다 놓기 · 무료 사진 검색(출처 자동 기입) · 사진 빼기. 자리는 **자동·배경·왼쪽·오른쪽·자유** |
| **자유 사진** | 아무 위치에나 놓기 · 끌어서 이동 · 점을 끌어 크기 조절 · 자르기(틀 안에서 사진만 이동). **한 장에 여러 개** |
| **투명도** | 사진 — 고른 자유 사진의 투명도, 없으면 **배경 사진에 자동으로 깔리는 막(`--veil-a`)의 두께**. 글자 — 고른 글자(없으면 커서 있는 문단). **슬라이더를 끄는 동안 바로 바뀐다** |
| **자유 사진 순서** | 앞으로 · 뒤로 (겹쳤을 때 누가 위인지). 되돌리기에 함께 잡힌다 |
| **사진 고르기** | 자유 사진·본문 사진·배경 사진 **아무거나 눌러서** 고른다. 고른 사진은 투명도·자르기·크기의 대상이 된다 |
| **사진 크기** | 고른 사진의 오른쪽 아래 파란 점을 끌어서 |
| **자르기** | 자르기를 켜고 사진을 끌면 **손이 간 만큼** 사진이 움직인다. 사진이 틀에 딱 맞으면 자를 여유가 없다고 알려 준다 |
| **글자 상자** | 글자 **위**를 누르면 커서, 글자 **밖**을 누르면 상자가 선택된다(초록 테두리). 고른 상자는 **끌어서 옮기고**, 오른쪽 아래 초록 점으로 **폭·최소 높이**를 바꾼다. 옮기지 않고 한 번 더 누르면 선택이 풀리고, 다시 누르면 커서가 들어간다. **원래 자리는 비워 둔 채 밀리는 방식**이라 뒤에 빈칸이 남는다 |
| **되돌리기 / 다시하기** | 버튼 또는 Ctrl+Z / Ctrl+Shift+Z. **60단계**(사진이 많으면 용량 상한이 먼저 걸린다). 글자 입력은 **단어 단위**로 끊어 쌓인다 |
| **슬라이드 이동** | 사이드바 **슬라이드 목록** 클릭 (편집 상태 유지) · PageUp/PageDown · 이전/다음 버튼 |
| 브랜드 색 | 프리셋 6종 → **밑색 하나로 세 색이 한꺼번에 바뀜** → 쉐이드 10단계에서 각각 다시 선택 (Canva의 Shade 방식). **쉐이드 줄은 언제나 '밑색' 기준이라 단계를 골라도 줄이 움직이지 않는다.** 색마다 **고정** 버튼이 있어, 켜 두면 밑색·프리셋을 바꿔도 그 색만 그대로 남는다 |
| 라이트/다크 | 버튼 (테마 항목 따로) |
| 로고 위치 | 4개 모서리 — **로고 파일이 없으면 이 항목 자체가 안 보인다** |
| 슬라이드 편집 | 복제 · 삭제 · 앞뒤 이동 · **목록을 끌어서 순서 바꾸기** |
| 제목 | 입력칸 (꼬리말·저장 파일명에 반영) |
| **저장** | **HTML로 저장**(새 파일 내려받기) 또는 **PDF로 저장**(인쇄 창) |

PDF로 저장할 때 인쇄 창에서 대상을 "PDF로 저장", 여백을 "없음", 배경 그래픽을 켜면
16:9 비율 그대로 나온다.

**설계상 지켜지는 것**

- **차트 숫자를 고치면 막대 길이가 자동으로 다시 비례한다.** 손으로 고치다 데이터를
  왜곡하는 일이 구조적으로 막힌다
- 색을 바꿔도 `palette.mjs`와 **같은 규칙**이 브라우저에서 돌아 대비 기준이 유지된다.
  기준을 못 넘기는 색을 고르면 패널에 경고가 뜬다
- 저장은 **열려 있는 파일을 덮어쓰지 않는다.** 새 파일이 내려받기 폴더에 생긴다
- 저장된 파일에도 편집기가 들어 있어 다시 열어 계속 고칠 수 있다

**한계**

- 새 슬라이드 유형 추가는 편집기로 안 된다 (복제 후 내용을 고치는 방식)
- 대화창 미리보기에서는 내려받기가 막힐 수 있다. 파일을 내려받아 브라우저로 직접 열면 된다

## 12. 작업 순서 (AI가 따르는 절차)

1. **내용을 먼저 확정한다.** 보고서·기획안·발표 대본을 읽는다. 자료가 없으면 주제·청중·발표
   시간을 물어보고, 빈 껍데기부터 만들지 않는다
2. **로고를 찾는다.** 작업 폴더 안의 `logo.png`. 없으면 넘어간다
3. **색을 정한다.** 로고·브랜드 색이 있으면 `palette.mjs` 실행 → 나온 블록을 통째로 교체.
   없으면 무채색 기본값 그대로
4. **슬라이드 흐름을 짠다.** 장마다 "청중이 가져갈 한 문장"을 먼저 적는다
5. `template.html`을 읽어 컴포넌트 마크업을 확인한다
6. 템플릿을 복사해 내용을 교체한다. **`:root`(색 블록 제외)와 `<script>` 엔진은 안 건드린다.**
   `<title>`을 발표 제목으로 바꾼다
7. 사진을 넣으면 리사이즈·압축·base64, 출처 표기
8. **두 겹으로 검증한다** — 자동 검사 → AI 시각 검토 → 수정 → 재검토
9. `제목, 만든 날짜.html`로 저장
10. 전달한다

## 13. 알아둘 것

### 덱은 템플릿의 사본을 품고 있다

완성된 HTML 파일 안에는 **만들 당시의 템플릿 CSS가 통째로 들어가 있다.** 나중에 템플릿을
개선해도 이미 만든 덱에는 반영되지 않는다.

옛 덱을 고칠 때는 **슬라이드 본문만 떼어 새 템플릿에 다시 얹는다.**
(덱에 새 클래스를 붙여도 그 클래스를 알아듣는 규칙이 옛 사본에 없어 아무 일도 안 일어난다.)

### 자동 검사는 절반만 잡는다

이 스킬을 만들며 나온 결함들은 **대부분 자동 검사를 전부 통과한 상태**였다.

- 강조 글자가 본문보다 흐려 위계가 뒤집힌 것 → 대비 검사는 통과 (읽히기는 하니까)
- 사진 33%가 잘려 나간 것 → 넘침 검사는 통과 (요소는 안 넘쳤으니까)
- 차트 막대가 값에 비례하지 않은 것 → 눈으로도 거의 안 보임
- 소제목이 "파랑·노랑 막대"라는데 화면은 회색·검정이던 것 → 기계는 글과 그림을 대조 못 함

그래서 **AI 시각 검토가 선택이 아니라 필수 단계**다.

### 이 스킬이 다루지 않는 것

- 실제 `.pptx` 파일 생성 → `pptx` 스킬
- A4 인쇄 문서 → 별도 문서 스킬
- 애니메이션·영상 삽입 → 지원하지 않음 (모션은 페이드인 하나뿐)

## 14. 결정 이력 (왜 이렇게 정했나)

| 결정 | 이유 |
|---|---|
| .pptx가 아니라 단일 HTML | 폰트를 CSS에 심어 어디서 열어도 안 깨짐 |
| 1920×1080 고정 | 사용자 지정 |
| 색 배분 65:25:10 | 사용자가 위임, Claude가 제안 |
| 다크/라이트를 고정하지 않음 | 사용자 지정 |
| 아이콘을 쓰지 않음 | "난잡해 보일 수 있다"는 사용자 판단 |
| 사진은 원본 색 그대로 | 사용자 선택 (듀오톤·흑백 대안 대신) |
| 사진 출처는 좌측 하단 | 사용자 지정, 출처 관례상 안전 |
| 로고 좌하단이면 출처는 우하단으로 | 두 요소가 겹치는 것을 방지 |
| 전환 모션은 빠른 페이드인만 | 사용자 지정, 절제된 모션 취향과 일치 |
| 출력 파일명 "제목, 만든 날짜.html" | 사용자 지정 |
| 목차는 좌측 타이틀 + 우측 하단 리스트 | 사용자 확인 |
| 2단 기본 + 4가지 예외 | 사용자 선택 |
| 소제목 = 제목 아래 보조 설명문 | 사용자 확인 (배경 워터마크 아님) |
| 로고는 작업별 하위 폴더에 보관 | 사용자 선택 (작업마다 로고가 다를 수 있어서) |
| 차트는 축 없이 값 직접 표기 | 사용자가 예시 3안 중 선택 |
| 브랜드 색 모르면 무채색 | 사용자 지정 (개인 이용이라 로고 없는 경우가 많음) |
| 라벨용 색과 강조용 색을 분리 | AI 시각 검토가 위계 역전을 발견해서 |
| 막대 비례 자동 검사 추가 | AI 시각 검토가 데이터 왜곡을 발견해서 |
| 브라우저 편집 모드 추가 | 사용자 요구 — PPT처럼 직접 고치고 싶음 |
| 편집기 색 변경도 팔레트 규칙을 그대로 적용 | 손으로 고치다 대비가 깨지는 것을 막기 위해 |
| 편집 저장 = 새 파일 내려받기 | 브라우저는 열려 있는 로컬 파일을 덮어쓸 수 없음 |
| pptx 대신 HTML·PDF 두 가지로 저장 | 사용자 요구 — pptx는 폰트 깨짐 문제로 애초에 안 씀 |
| 목차 제목을 좌측 위로 | 사용자 요구 (기존 좌측 아래에서 변경) |
| 색 프리셋·견본 추가 | 사용자 요구 — 직접 고르기만으로는 고르기 어려움 |
| 형광펜·굵게 강조 기능 | 사용자 요구 |
| 로고 없으면 사이드바에서 로고 항목 숨김 | 사용자 요구 — 쓸 수 없는 항목이 보이면 혼란 |
| 출처 표기 자동 검사(`citations`) | 사용자 요구 — 논문 인용 시 출처를 철저히 |
| 목록 드래그로 순서 변경 | 사용자 요구 |
| 목차를 O 키 대신 구석 버튼으로 | 사용자 요구 |
| 형광펜 지우기 방식 변경 | 버그 — 선택을 감싼 강조가 안 풀렸음. 선택과 겹치는 강조를 전부 벗기는 방식으로 교체 |
| 색을 쉐이드 단계에서 고르기 | 사용자 요구 (Canva의 Shade, 제작자 Nafis Azizi Riza 방식) |
| 사진 넣기 세 가지 경로 | 사용자 요구 — 만들 때·편집기 검색·내 파일 |
| 목록에서 표지·목차·마무리를 '메인/목차/마무리'로 부름 | 사용자 요구 |
| 표지 출처를 오른쪽 아래로 | 버그 — 좌하단 발표자·일시와 겹쳤고, 글자색도 어두워 안 보였음 |
| 되돌리기/다시하기(20단계) | 사용자 요구. 무대 전체 스냅샷 방식 |
| 자유 사진(이동·크기·자르기) | 사용자 요구 — 한 장에 한 개만 넣을 수 있었음 |
| 사진·글자 투명도 | 사용자 요구 |
| 투명도 슬라이더를 끌기만으로 적용 | 사용자 요구(명세 6-1). 누르는 순간 선택이 사라지므로 `selectionchange`로 미리 기억해 두고, 끌기 시작할 때 span을 한 번만 씌운 뒤 값만 바꾼다 |
| 자리 버튼에 **자유** 합류 | 사용자 요구(명세 6-2). 별도 버튼이 아니라 자동·배경·왼쪽·오른쪽과 같은 줄 |
| 표지 사진 출처를 목차에 아주 작게 | 사용자 요구(명세 6-3). 표지 좌하단 발표자·일시와 겹치는 문제를 자리 이동이 아니라 **장 이동**으로 해결 |
| 표지에서 왼쪽/오른쪽 사진 | 버그(명세 6-4) — 표지에는 `.body-main`이 없어 실패했음. 반쪽 bleed 사진으로 대체 |
| 배경 막 두께를 사진 슬라이더로 | 사용자 요구(명세 6-5). `--veil-a` 하나로 라이트·다크·표지 그라데이션이 함께 움직인다 |
| 되돌리기를 단어 단위로 끊기 | 버그(명세 6-6) — 0.6초만 안 쉬면 문단 전체가 한 뭉치라 "한 번밖에" 되돌아갔음 |
| `word-break:keep-all` | 사용자 요구(명세 6-7). 한글이 글자 단위로 잘리지 않고 어절이 통째로 넘어간다 |
| 배경 사진을 눌러서 고르기 | 버그(명세 9-1) — 배경은 글 뒤(z-index:0)에 깔려 있어 눌러도 절대 안 잡혔다. 사진·글자가 아닌 빈 자리를 누르면 그 장의 배경 사진을 고른 것으로 본다 |
| 고르기 창을 닫아도 오류 메시지가 안 뜨게 | 버그(명세 9-1) — 취소하면 "이미지 파일만 넣을 수 있습니다"가 떴다 |
| 사라진 노드를 가리키던 `selFloat` 정리 | 버그(명세 9-1) — 사진을 뺀 뒤 `getComputedStyle(null)` 에서 죽어 그다음 동작이 전부 먹통이 됐다 |
| 글자 상자 끌어서 옮기기 | 사용자 요구(명세 9-2). `absolute` 로 바꾸면 배치가 무너지므로 **원래 자리는 두고 `transform` 으로만 민다** — 뒤에 빈자리가 남는 것은 그 대가다 |
| 넘침 검사를 네 방향 + 옮긴 상자까지 | 상자와 사진을 자유롭게 옮길 수 있게 되면서, 아래쪽만 보던 검사로는 옆으로 나간 것을 놓쳤다 |
| 글자 상자를 '글자 위'에서만 잡기 | 버그(명세 8-1) — 블록은 글자가 짧아도 줄 끝까지 늘어나 있어 빈 자리를 눌러도 커서가 들어갔다. 누른 점이 실제 줄상자 안인지 먼저 본다 |
| 글자 상자 폭·최소 높이 조절 | 사용자 요구(명세 8-5). 손잡이는 상자 안이 아니라 무대 위에 따로 띄운다 — 안에 넣으면 편집 내용에 섞여 저장된다 |
| 고정한 색의 가독성 경고 | 사용자 요구(명세 8-2). 표지·마무리 바탕, 형광펜 배경, 강조 카드 배경, 패널 라벨, 색끼리의 구분까지 본다. 고정된 색이 원인이면 그렇게 알린다 |
| 보조색에 실제 면적 주기 | 사용자 지적(명세 8-3) — `--c-sub` 를 쓰는 곳이 두 군데뿐이라 보조색을 바꿔도 화면이 거의 안 바뀌었다. **마무리 장 전체 배경**, 단계 번호, 패널 제목 밑줄, 강조 카드가 보조색이 됐다 |
| 어떤 사진이든 눌러서 고르기 | 사용자 요구(명세 8-6, 8-10). 자유 사진뿐 아니라 본문 사진·배경 사진도 고르면 투명도·자르기·크기의 대상이 된다 |
| 자르기를 손 움직임과 1:1 로 | 버그(명세 8-7) — 이동량에 0.12 를 곱해서 200px 을 끌면 37% 가 튀었다. '잘려 나간 여유(px)' 로 나눠 손이 간 만큼만 움직인다. 여유가 0 이면 그렇게 알린다 |
| 표지 배경 사진에 그라데이션 마스크 | 사용자 요구(명세 8-8). 막을 덧씌우는 대신 **사진 자체가 글자 쪽에서 바탕색으로 녹아든다**. 글자가 놓이는 자리는 순수한 주조색이라 대비가 보장된다 |
| `.float-img` 를 position 재정의에서 제외 | 버그(명세 8-9) — 배경 사진이 있는 장에서 자유 사진이 `relative` 가 되어 본문 흐름에 끌려 들어갔다 |
| 끌고 난 뒤 선택이 풀리던 것 | 버그(명세 8-4의 원인) — 끌면 `click` 이 슬라이드에서 떠서 선택 해제 규칙에 걸렸다. 끌기 중이면 건너뛴다 |
| 차트 막대 폭 96 → 168px | AI 시각 검토 지적 — 막대가 가늘어 길이 비교가 안 됐다 |
| 사진과 출처 줄을 `data-credit-key`로 묶기 | 사용자 요구(명세 7-1) — 표지 사진을 빼도 목차의 출처 줄이 남았음. 각주가 든 `.cite`는 열쇠에서 제외 |
| 자유 사진 앞/뒤 순서 | 사용자 요구(명세 7-2). z-index를 직접 적지 않고 언제나 3,4,5…로 다시 매긴다 — 삭제·복제를 거쳐도 번호가 어긋나지 않는다 |
| 색 **고정** 버튼 | 사용자 제안(명세 7-3). "손댄 색은 자동으로 지킨다"는 무엇이 지켜지는지 알 수 없어서, 붙잡아 둘 색을 직접 고르게 했다 |
| 쉐이드 줄의 기준을 '밑색'으로 고정(`--c-base`) | 버그(명세 6-8) — 예전에는 '지금 주조색'에서 줄을 다시 만들어서, 300단계를 고르면 (이미 채도가 한 번 빠진 색이라) 줄 전체가 씻긴 색으로 바뀌고 방금 고른 칸 표시도 사라졌다. 고를 때마다 색이 달라져 되돌릴 수 없었다 |
| 목차를 드롭다운으로 | 사용자 요구 — 전체화면 오버레이가 과함 |
| 사진 넣는 자리 4종(자동·배경·좌·우) | 사용자 요구 — 교체만 되고 '추가'가 안 됐음 |
| 밑색 하나로 세 색이 함께 바뀜 | 사용자 요구 — 주조색만 바뀌던 것을 배색 전체로 |
