# Slides-in-Html

발표 화면에 띄우거나 화면 공유로 보여주는 **단일 HTML 파일 하나**를 만든다. PPTX와 달리 폰트를
CSS에 직접 심기 때문에 어느 기기·브라우저에서 열어도 글자가 깨지지 않고, 반응형으로 화면 크기에
맞춰 통째로 scale 된다.

## 스킬에 들어 있는 것

```
assets/
├── template.html    슬라이드 엔진 + 13장 예시 (여기서 시작한다)
├── style-guide.md   색·타이포·라운드·로고·사진·차트 규칙 원본
├── palette.mjs      브랜드 색 3개 → :root 색 토큰 블록 생성 (대비 자동 계산, 의존성 없음)
├── check.mjs        기계가 잡는 것 7종 자동 검사 + 전체 스크린샷 (playwright)
└── review-prompt.md 기계가 못 잡는 것(위계·여백·의미)을 서브에이전트에게 보게 하는 프롬프트

RULES.md            규칙·명령 전체를 사람이 읽기 좋게 정리한 참조서 (헷갈리면 여기를 본다)
```

## 작업 순서

1. **내용을 먼저 확정한다.** 사용자가 준 보고서·기획안·발표 대본을 읽는다. 자료가 없으면
   주제·청중·발표 시간을 물어보고, 빈 껍데기부터 만들지 않는다.
2. **로고 파일을 찾는다.** 연결된 폴더 안에서 이번 작업의 하위 폴더(예: `내폴더/2026-분기보고/`)에
   `logo.png`가 있는지 먼저 본다. 로고를 넣을 모서리(기본 우측 하단)도 확인한다.
3. **색을 정한다.** 순서가 중요하다.
   - 로고가 있거나 사용자가 브랜드 색을 알려주면 → `node assets/palette.mjs "#주조" "#보조" "#강조"`를
     실행하고, 나온 블록 두 개를 `:root`와 `html[data-theme="dark"]`에 그대로 붙여넣는다.
     **색 세 개만 손으로 바꾸지 않는다** — 글자용 색과 차트 강조색은 대비 계산으로 정해지는 값이다.
   - **로고도 없고 브랜드 색도 모르면 → 색을 지어내지 말고 무채색 기본값을 그대로 쓴다.**
     템플릿이 이미 무채색이라 아무것도 안 해도 된다. 사용자에게 "무슨 색으로 할까요"를 되묻지 않는다.
     개인적으로 쓰는 자료는 로고가 없는 경우가 많고, 그때 임의의 색을 넣는 것보다 무채색이 낫다.
   - 라이트/다크 중 어느 쪽을 쓸지도 이때 정한다.
4. **슬라이드 흐름을 짠다.** 기본 골격은 이것이다.

   ```
   표지 → 목차 → 본론(좌우 2단 기본 + 예외 4유형 반복) → 마무리
   ```

   각 본론 슬라이드마다 **"이 장에서 청중이 가져갈 한 문장"**을 먼저 적고, 그 문장에 맞는
   컴포넌트를 아래 표에서 고른다. 2단이 기본이지만 인용구·큰 수치·개념 한 문장·사진 1장이
   주인공인 슬라이드는 1단으로 만든다.
5. `assets/template.html`을 Read로 열어 컴포넌트 마크업을 확인한다.
6. 템플릿을 작업 폴더로 복사한 뒤 그 위에서 내용을 교체한다.
   `<style>`의 `:root`(색 토큰 블록만 palette.mjs 출력으로 교체)와 하단 `<script>` 엔진은
   **건드리지 않는다.**
   `<title>`은 발표 제목으로 바꾼다(꼬리말 왼쪽이 `document.title`에서 자동으로 채워진다).
   `#stage`의 `data-logo` 속성을 원하는 모서리로 바꾸고, `data-theme="dark"`를 `<html>`에
   붙일지 결정한다.
7. **사진을 넣을 땐** 원본 색 그대로, 최대 가로 1600px로 리사이즈·압축한 뒤 base64로 심는다.
   출처를 `.credit`에 적는다(로고가 좌측 하단이면 자동으로 우측 하단으로 이동하니 신경 쓰지 않아도 된다).
8. **두 겹으로 검증한다**(아래 "검증" 참고). 자동 검사를 통과시킨 뒤, 스크린샷을 서브에이전트에게
   보여 시각 검토까지 받는다. 자동 검사만으로는 부족하다 — 실제로 결함의 대부분은 검사를 통과했다.
9. `제목, 만든 날짜.html` 형식으로 파일명을 짓는다 (예: `2026 3분기 실적보고, 2026-08-26.html`).
   완성된 덱은 템플릿 CSS의 **사본**을 품고 있다. 나중에 템플릿이 개선돼도 이미 만든 덱에는
   반영되지 않으므로, 옛 덱을 고칠 때는 슬라이드 본문만 떼어 새 템플릿에 다시 얹는다.
10. SendUserFile로 전달한다. 기기가 연결돼 있으면 device_commit_files로 로고와 같은 폴더에 저장한다.

## 반드시 지킬 규칙

**무대는 1920×1080(16:9) 고정.** 슬라이드마다 `padding:96px 120px 84px`이 잡혀 있고 화면 크기에
맞춰 통째로 scale 된다. px 단위를 그대로 쓰고 %·vw·vh로 바꾸지 않는다. 내용이 넘치면 글자를
줄이는 게 아니라 **슬라이드를 나눈다.**

비율을 지키는 장치가 두 개 있다. 둘 다 지우면 16:9가 깨진다.

- `#stage`의 **`flex:0 0 auto`** — 없으면 창이 1920px보다 좁을 때 무대가 가로로 찌그러진다
  (flex 아이템 기본 `flex-shrink:1`이 `width:1920px`을 무시하고 줄인다)
- `@page`의 **`size:20in 11.25in`** — px로 적으면 브라우저가 무시하고 Letter/A4로 인쇄한다
- `fit()`은 창이 아니라 **`#deck`의 실제 크기**를 잰다 — 편집기 패널이 열려도 넘치지 않는다

**색은 주조 65% : 보조 25% : 강조 10%.** 강조색은 한 슬라이드에 한두 군데만 — 여러 번 쓰면 이미
강조가 아니다. 색 토큰은 `palette.mjs`가 만든 블록을 통째로 갈아 끼우고, 개별 값을 손으로 고치지
않는다. `--c-main-text`(조용한 라벨), `--c-emph`(본문 안 강조), `--c-chart-hi`(차트 강조 막대),
`--on-main`/`--on-sub`/`--on-accent`(그 면 위 글자)는 전부 대비 계산 결과다.
**본문 안 강조에는 `--c-emph`를 쓴다** — 라벨용 색을 쓰면 무채색에서 강조가 본문보다 흐려진다.

**브랜드 색을 모르면 무채색.** 로고가 없고 사용자도 색을 지정하지 않았으면 템플릿 기본값(무채색)을
그대로 쓴다. 색을 임의로 골라 넣지 않는다.

**명도 대비 최소 기준(WCAG).** 본문 텍스트는 배경 대비 4.5:1 이상, 큰 텍스트(24px 이상 또는
18.66px 이상이면서 굵게)는 3:1 이상, 차트 막대는 배경과도 서로끼리도 3:1 이상. 이미지 잘림은 15% 미만, 막대 비례 오차는 5% 미만.
`check.mjs`가 이 기준들과 출처 표기까지 일곱 가지를 자동으로 검사한다.

**색 세 개는 실제로 다른 자리를 맡는다.** 주조 65%(표지 배경·차트 막대·표 머리·목차 현재 위치),
보조 25%(**마무리 장 전체 배경**·단계 번호·패널 제목 밑줄·강조 카드), 강조 10%(주의 콜아웃·형광펜).
보조색이 눈에 안 띄면 배색이 아니라 **쓰인 자리가 없는 것**이다.

**표지에 배경 사진을 넣으면 글자 쪽에서 사진이 사라진다.** 막을 덧씌우는 대신 마스크로 사진을
바탕색에 녹여, 글자가 놓이는 자리는 순수한 주조색이 된다. 그래서 표지 글자 대비는 사진과 무관하게
보장된다. 직접 마크업할 때도 `.slide.cover.has-bgphoto` 만 붙이면 된다.

**줄 나눔은 단어 기준이다.** `.slide`의 `word-break:keep-all`이 그 일을 한다.
제목에 `<br>`을 직접 넣을 때도 **어절 중간에서 끊지 않는다.**

**라이트/다크는 고정하지 않는다.** `<html data-theme="dark">` 유무로 매번 고른다.

**제목 웨이트는 600.** 800·900으로 올리지 않는다. `letter-spacing`은 `normal`로 둔다.

**선과 그림자를 쓰지 않는다.** 영역은 `--panel` 배경 면과 20px 라운드로 나눈다. 카드 테두리가
필요하면 `2px solid var(--line)`까지만.

**아이콘을 쓰지 않는다.** 개념을 시각화할 때는 아이콘 대신 **사진**을 쓴다. 사진은 보정 없이
원본 색 그대로, 듀오톤·흑백 처리하지 않는다.

**전환 모션은 빠른 페이드인 하나뿐.** 슬라이드 전환과 단계 공개(`step-in`) 모두 같은 모션이다.

## 슬라이드 유형과 마크업

템플릿에 13장의 실제 예시가 들어 있다. 필요한 유형을 복제해 내용만 바꾼다.

| 유형 | 클래스 | 쓰는 자리 |
|---|---|---|
| 표지 | `.slide.cover` | 큰 제목 + 부제 + 발표자/일시. 로고는 `data-logo`가 지정한 모서리에 자동 배치 |
| 목차 | `.slide.toc` > `.agenda` > `.ag` | **좌측 위**에 큰 "목차" 타이틀 + **우측 아래** 항목 리스트. `.now`로 현재 위치, `.done`으로 지난 항목 |
| 본론 — 소제목 | `.shead` > `.eyebrow` + `h2` + `.sub` | `.sub`는 배경 워터마크가 아니라 **제목 바로 아래 붙는 보조 설명문**(50% 투명도) |
| 본론 — 좌우 2단(기본) | `.two` / `.two.w7` / `.two.w3` | 좌우 1:1 / 1.35:1 / 1:1.35. 본론의 기본값 |
| 예외 ① 인용구 | `.quote` | 고객·경영진 발언 등 문장 하나를 강조할 때. 1단 |
| 예외 ② 큰 수치 | `.bignums` / `.bignums.panels` | 숫자 1~3개를 크게 강조할 때. 1단. 숫자만 두면 화면이 허전하니 `.panels`로 면을 준다 |
| 예외 ③ 개념 한 문장 | `.message` | 핵심 메시지를 한 줄로 못박을 때. 1단 |
| 예외 ④ 사진 1장 | `.photo-hero` / `.photo-hero.fit` | 사진 한 장이 주인공일 때. 1단. `.credit`로 출처 표기. **스크린샷·도표는 반드시 `.fit`** — 기본값은 가장자리를 잘라낸다 |
| 차트 | `.chart` > `.bars` > `.bar` | 축·그리드라인 없이 막대 위에 값을 직접 표기. `.bar.hi`로 하나만 `--c-chart-hi` 적용 |
| 카드 그리드 | `.grid.g2` `.g3` `.g4` > `.card` | 상황별 선택지·우선순위. `.card.hi`로 하나 강조 |
| 비교표 | `.ctable` | 분기별·항목별 비교 |
| 단계 | `.steps` > `.step` | 실행 계획을 3~4단계로 |
| 정리 리스트 | `.mlist` | 오늘 가져갈 것 3~4개 |
| 강조·주의 | `.callout` / `.callout.warn` | 리스크·주의사항 한 줄 |
| 마무리 | `.slide.closing` | 감사 인사·Q&A·다음 단계 안내 |

레이아웃 보조 클래스

- `.body-main.center` — 내용을 세로 가운데로 (내용이 적을 때 반드시 붙인다)
- `.fill` — 남은 세로 공간을 채운다
- `.stack` / `.panel` — 2단 안에서 세로로 쌓을 때

## 로고

- `#stage`에 `data-logo="tl|tr|bl|br"`로 위치 지정 (기본 `br`, 우측 하단).
- 파일은 연결된 데스크톱 폴더 안 **작업별 하위 폴더**에서 `logo.png`로 찾는다.
- `<img class="logo" src="logo.png">`로 상대경로 삽입 — 최종 HTML을 로고와 같은 폴더에 저장한다.
- **로고가 없으면 그냥 넣지 않는다.** 파일이 없으면 `onerror`로 자동으로 숨겨지고, 그 자리는 비워
  두는 게 맞다. 로고를 찾느라 작업을 멈추거나 사용자에게 되묻지 않는다. 브랜드 색도 같이 모르는
  상황이므로 무채색 기본값으로 진행한다.
- 표지·마무리 슬라이드에서는 로고에 `filter:brightness(0) invert(1)`이 걸려 **흰색으로 찍힌다.**
  주조색이 밝아서 `--on-main`이 먹색으로 잡힌 경우에는 이 규칙을 지우고 원본 로고를 쓴다.

## 출처 표기 — 남의 것을 가져다 쓰면 반드시 적는다

**논문·통계·기사·인용문·사진 등 출처가 있는 것은 예외 없이 슬라이드 하단에 출처를 적는다.**
`check.mjs`가 자동으로 검사한다 — 인용문·각주·사진이 있는데 출처가 없으면 통과하지 못한다.

| 클래스 | 쓰는 자리 |
|---|---|
| `.cite` | 논문·통계·기사·인용문 출처. 여러 줄 가능 |
| `.credit` | 사진 한 줄 출처 |
| `.credit-mini` | **표지·마무리 사진의 출처를 목차에 모아 적는 아주 작은 줄**(13px) |
| `.ref` | 본문에서 인용한 자리에 붙이는 각주 번호 |

```html
<blockquote>인용한 문장입니다.<span class="ref">1</span></blockquote>
...
<div class="cite">
  <span><b>1</b> 홍길동, 「논문 제목」, 학회지 12(3), 2025, pp.44-58.</span>
  <span><b>2</b> 통계청, 「2026 사회조사」, 2026.</span>
</div>
```

- **각주 번호를 달았으면 `.cite`에 같은 번호가 있어야 한다.** 없으면 검사에 걸린다
- 출처에는 **저자·제목·출처·연도**를 적는다. "논문에서" 같은 뭉뚱그린 표기는 출처가 아니다
- 페이지·표 번호까지 있으면 함께 적는다
- `.cite`와 `.credit`은 자리가 같다. 사진과 인용이 함께 있으면 `.cite` 하나에 모아 적는다
- **표지·마무리에 사진을 넣었으면 출처를 그 장이 아니라 목차에 적는다.** 표지 좌하단에는
  발표자·일시가 있어 겹친다. 목차 맨 아래에 `<div class="credit-mini"><span>사진: …</span></div>`
  를 두면 된다. `citations` 검사도 이 자리를 보고 통과시킨다
- 편집기가 넣은 출처 줄은 `data-credit-key`로 사진과 짝지어져 있어, 사진을 빼면 줄도 같이
  사라진다. 손으로 적을 때는 신경 쓰지 않아도 된다

## 사진 · 출처

**사진을 넣을 자리가 있으면 넣는다.** 표지와 사진 슬라이드는 사진이 있을 때 훨씬 낫다.
넣는 방법은 세 가지이고, 상황에 맞는 것을 고른다.

1. **만들 때 Claude가 넣기** — 이미지를 받아올 수 있는 환경이면, 발표 주제에 맞는
   자유 이용 사진(위키미디어 공용·Unsplash 등)을 찾아 리사이즈·압축 후 base64로 심고,
   `.credit`에 **저작자·라이선스·출처**를 적는다.
   **받아올 수 없는 환경이면 억지로 넣지 말고**, 자리를 비워 둔 채 사용자에게
   "편집 모드(E)의 사진 기능으로 직접 넣으시면 됩니다"라고 알린다. 아무 사진이나 지어내지 않는다.
2. **편집기에서 검색** — 사용자가 E 편집 모드에서 단어를 넣어 무료 사진을 찾아 고른다.
   출처가 자동으로 적힌다.
3. **내 파일 끌어다 놓기** — 인터넷 없이도 된다. 이 경우 출처는 자동으로 안 적히므로 직접 적는다.

표지에 사진을 깔면 **어두운 막이 자동으로 함께 깔린다.** 사진 위 글자의 대비를 보장할 수 없기
때문이고, 이 막은 끄지 않는다.

- 원본 색 그대로 사용, 듀오톤·흑백 안 함. 아이콘 대신 사진으로 개념을 보여준다.
- 리사이즈(최대 가로 1600px) + 압축 후 base64로 심는다.
- **`.photo-hero`의 기본값은 상자를 꽉 채우는 대신 이미지 가장자리를 잘라낸다.**
  스크린샷·도표·글자가 든 이미지는 잘리면 안 되므로 `<div class="photo-hero fit">`로 쓴다.
  분위기용 사진만 기본값(잘림 허용)으로 둔다. 잘린 비율이 15%를 넘으면 `check.mjs`가 잡아낸다.
- 출처는 `.credit`(기본 좌측 하단)에 작게 표기. **로고가 좌측 하단이면 엔진이 자동으로
  `body.credit-flip`을 붙여 출처를 우측 하단으로 옮긴다** — 직접 클래스를 건드리지 않는다.

## 한 단계씩 공개하기

바로 보이면 안 되는 것(리스크, 다음 단계 예고 등)에는 `step-in`을 붙인다. → 를 누르면 다음
슬라이드로 가기 전에 `step-in` 요소가 순서대로 하나씩 나타난다.

```html
<div class="callout warn step-in">…</div>
```

인쇄할 때는 전부 펼쳐져서 나온다.

## 편집 모드 (E 키)

만든 뒤 사용자가 브라우저에서 직접 고칠 수 있다. 발표 기능과 분리돼 있어 편집기를 지워도
발표는 그대로 된다.

| 할 수 있는 것 | 방법 |
|---|---|
| 글자 고치기 | 글자를 눌러 바로 입력 |
| 브랜드 색 바꾸기 | 프리셋 6종 → **밑색 하나를 고르면 주조·보조·강조가 한꺼번에 그 색 계열로 바뀐다**(주조=고른 색, 보조=800, 강조=900). 이어서 쉐이드 10단계에서 각각 다시 고를 수 있고, **줄 자체는 밑색 기준으로 고정**이라 몇 번을 골라도 색이 밀리지 않는다. 색마다 **고정** 버튼이 있어 켜 둔 색은 밑색·프리셋을 바꿔도 그대로 남는다. 밑색은 `--c-base` 로 파일에 함께 저장된다 |
| 무채색으로 되돌리기 | 버튼 하나 |
| 라이트/다크 전환 | 버튼 |
| 로고 위치 | 4개 모서리 버튼 — **로고 파일이 없으면 이 항목 자체가 안 보인다** |
| 슬라이드 복제·삭제·순서 | 버튼, 그리고 **목록을 끌어서 순서 바꾸기** |
| 제목 바꾸기 | 입력칸 (꼬리말과 저장 파일명에 반영) |
| 글자 강조 | 끌어서 선택 후 **형광펜 · 굵게 · 지우기**. 지우기는 강조 위에 커서만 놓아도 풀린다 |
| **사진 넣기** | 내 파일 끌어다 놓기 · 무료 사진 검색 · 사진 빼기. 자리는 **자동·배경·왼쪽·오른쪽·자유**. 표지처럼 본문 틀이 없는 장에서 왼쪽/오른쪽을 고르면 반쪽을 사진이 채우고 글이 반대쪽으로 밀린다 |
| **자유 사진** | 자리에서 **자유**를 고르고 넣으면 슬라이드 아무 데나 놓인다. **끌어서 옮기고, 점을 끌어 크기를 바꾸고, 자르기로 틀 안에서 사진만 움직인다**. 한 장에 여러 개 가능하고 **앞으로·뒤로**로 겹치는 순서를 바꾼다 |
| **사진 고르기·크기·자르기** | 자유 사진·본문 사진은 사진을, **배경 사진은 글자 없는 빈 자리를** 눌러서 고른다. 오른쪽 아래 점을 끌어 크기를, 자르기를 켜고 끌어 보이는 부분을 바꾼다 |
| **글자 상자** | 글자 **위**를 누르면 커서, 글자 **밖**을 누르면 상자 선택 → **끌어서 옮기거나** 오른쪽 아래 점으로 **폭·최소 높이** 조절 (원래 자리는 비워 둔 채 밀린다) |
| **투명도** | 사진 — **고른 사진**의 투명도, 배경 사진이면 **위에 깔리는 막의 두께**(100%=막 없음). 글자 — 끌어서 선택한 글자. **슬라이더를 끄는 동안 바로 바뀐다** |
| **되돌리기 / 다시하기** | 버튼 또는 **Ctrl+Z / Ctrl+Shift+Z**. 60단계, 글자 입력은 **단어 단위**로 끊긴다 |
| 슬라이드 이동 | 사이드바 **슬라이드 목록**을 눌러 이동 (편집 상태 유지). PageUp/PageDown도 됨 |
| 저장 | **HTML로 저장** (편집 내용을 담은 새 파일) 또는 **PDF로 저장** (인쇄 창) |

- **차트 숫자를 고치면 막대 길이가 자동으로 다시 비례한다** — 손으로 고치다 데이터를
  왜곡하는 일이 구조적으로 막힌다
- 색을 바꿔도 `palette.mjs`와 **같은 규칙**이 브라우저에서 돌아가므로 대비 기준이 유지된다
- 저장은 열려 있는 파일을 덮어쓰지 않는다. 새 파일이 내려받기 폴더에 생긴다
- 저장된 파일에도 편집기가 들어 있어 다시 열어 계속 고칠 수 있다

## 검증

**두 겹이다.** 기계가 잡는 것과 눈으로만 잡히는 것이 서로 다르고, 겹치지 않는다.

### 1겹 — 자동 검사 (기계가 잡는 것)

```bash
npm install playwright   # 없을 때만
node assets/check.mjs /절대경로/deck.html /출력폴더
# 슬라이드 번호를 생략하면 전체를 캡처한다 (시각 검토에는 전체가 필요하다)
```

- `overflow: []`가 아니면 그 슬라이드를 나눈다 — 1080px를 넘친 내용은 화면 공유에서 그냥 잘려 나간다
- `errors: []`가 아니면 마크업이 깨진 것이다
- `contrast(글자 대비 미달): []`가 아니면 그 요소의 배경색이나 글자색을 조정한다
  (`.sub`처럼 투명도를 쓰거나 `rgba()`로 쓴 색도 배경에 섞인 실제 색으로 환산해 검사한다)
- `graphics(막대 대비 미달): []`가 아니면 `palette.mjs`를 다시 돌려 `--c-chart-hi`를 받아 넣는다.
  그래도 안 되면 강조색 자체가 주조색과 밝기가 너무 비슷한 것이다
- `cropped(이미지 잘림): []`가 아니면 그 슬라이드의 `.photo-hero`에 `fit`을 붙인다
- `barScale(막대 비례 어긋남): []`가 아니면 막대 높이를 값에 비례하도록 고친다.
  축도 그리드도 없는 차트라 청중은 오직 길이로 값을 읽는다 — 비례가 틀리면 데이터를 왜곡하는 것이다
- `citations(출처 누락): []`가 아니면 그 슬라이드에 `.cite` 또는 `.credit`으로 출처를 적는다
- **다크 테마로 낼 거면 다크 상태로도 한 번 더 돌린다.** 밝은 테마만 통과하고 다크에서 깨지는 일이 잦다
- 슬라이드 번호를 뒤에 붙이면 그 장만 캡처한다(0부터). 생략하면 전체를 찍는다

### 2겹 — 시각 검토 (기계가 못 잡는 것)

자동 검사는 "확실히 틀린 것"만 잡는다. **시각 위계가 뒤집혔는지, 여백이 휑한지, 글과 그림이
다른 말을 하는지, 줄바꿈에 강조가 쪼개졌는지는 잡지 못한다.** 실제로 이 스킬을 만들 때 나온
결함의 대부분이 자동 검사를 전부 통과한 상태였다.

그래서 캡처가 끝나면 `assets/review-prompt.md` 의 내용을 그대로 **서브에이전트(Task/Agent 도구)**
에게 맡긴다. 경로 두 곳만 실제 값으로 바꿔 넣으면 된다. 서브에이전트는 스타일 가이드를 읽고
스크린샷을 한 장씩 열어 본 뒤, 슬라이드별로 문제와 고칠 방법을 돌려준다.

- 심각도 "높음"은 반드시 고친다.
- "중간"은 발표 성격을 보고 판단한다.
- 고친 뒤에는 **다시 캡처해서 한 번 더 검토를 받는다.** 한 번에 다 안 잡힌다.
