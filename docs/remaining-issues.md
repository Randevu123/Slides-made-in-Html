# Slides-in-Html — 남은 문제와 고칠 방법

2026-08-27 · 명세 9까지 반영한 뒤, 내가 직접 코드를 훑고 브라우저에서 돌려 보며 정리했다.
**심각도 순**이고, 각 항목은 "무엇이 문제인가 / 왜 문제인가 / 어떻게 고치면 되는가 / 드는 품" 순서다.
사용자가 겪은 증상이 아니라 **내가 찾아낸 것**이므로, 실제로 불편하지 않은 항목은 건너뛰어도 된다.

---

## 높음 — 자료가 망가지거나 잃어버릴 수 있는 것

### 1. 저장을 잊으면 편집이 통째로 사라진다

**무엇** 편집기에는 자동 저장이 없다. 30분을 고쳐도 **HTML로 저장**을 누르지 않고 탭을 닫으면 전부 사라진다. 브라우저가 "정말 나가시겠습니까?"를 묻지도 않는다.

**왜** 이 편집기는 발표 직전에 오탈자를 고치는 용도로 자주 쓰인다. 그 상황에서 실수로 탭을 닫는 일이 잦다. 되돌리기 60단계를 공들여 만들어 놓고 정작 이탈 방지는 없는 것은 앞뒤가 안 맞는다.

**고침** 두 겹으로 막는다.
- `beforeunload` 에 "저장하지 않은 편집이 있습니다" 를 붙인다. 편집을 한 번이라도 했을 때(`undoStack.length > 0`)만 뜨게 한다.
- 30초마다 `localStorage` 에 현재 무대를 넣어 두고, 파일을 다시 열었을 때 "지난번에 저장 안 한 편집이 있습니다. 되살릴까요?" 를 묻는다. 사진이 든 덱은 용량이 커서 `localStorage` 5MB 를 넘길 수 있으니, 넘치면 조용히 건너뛰고 `beforeunload` 만 남긴다.

**품** 작음(30줄 안팎). **이건 먼저 하는 게 좋다.**

---

### 2. 사진을 넣을수록 파일이 무거워지고, 되돌리기가 그 무게를 몇 배로 늘린다

**무엇** 사진은 가로 1600px·품질 0.82 로 줄여 base64 로 심는다. 한 장에 40~120KB 다. 10장에 사진 8개면 파일이 1MB 를 넘는다. 그런데 되돌리기 스냅샷은 **무대 전체 HTML 을 통째로 복사**하므로, 사진이 든 덱에서는 스냅샷 하나가 곧 파일 하나만큼 무겁다. 지금은 총 24MB·60단계에서 끊고 있어 터지지는 않지만, 사진이 많으면 되돌리기가 3~4단계밖에 안 남는다.

**왜** 사진을 많이 쓰는 사람일수록 되돌리기가 필요한데, 정확히 그 사람에게서 되돌리기가 가장 짧아진다.

**고침** 사진 데이터를 스냅샷에서 빼낸다. `img.src` 가 `data:` 로 시작하면 그 문자열을 별도 표에 한 번만 담고 스냅샷에는 열쇠(`#img7`)만 남긴다. 되돌릴 때 열쇠를 다시 데이터로 바꿔 끼운다. 스냅샷 크기가 수십 KB 로 떨어져 60단계가 사진과 무관해진다.
**품** 중간(50~80줄). 스냅샷·복원 두 곳만 손대면 된다.

---

### 3. 자유 사진과 글자 상자를 무대 밖으로 밀 수 있는데, 화면에서는 경고가 없다

**무엇** 자유 사진을 끌어 무대 오른쪽 밖으로 보내면 `#stage` 의 `overflow:hidden` 이 잘라 버린다. 화면에서는 그냥 사라진 것처럼 보인다. `check.mjs` 는 이제 네 방향을 다 보므로 잡지만(방금 고쳤다), **그건 파일을 저장하고 검사를 돌려야 알 수 있다.**

**왜** 편집 중에 바로 알려 주지 않으면, 사라진 사진을 찾느라 헤매거나 사라진 줄도 모르고 발표한다.

**고침** 끌기가 끝날 때 무대 밖으로 나갔는지 보고, 나갔으면 사이드바에 "이 사진의 일부가 화면 밖에 있습니다" 를 띄운다. 아예 무대 안으로 되밀어 넣는 것(clamp)은 의도적으로 반쯤 걸치게 두는 배치를 막으므로 하지 않는 게 낫다.
**품** 작음(15줄).

---

## 중간 — 자주 걸리지만 자료가 망가지지는 않는 것

### 4. 자유 사진 크기를 바꾸면 비율이 깨진다

**무엇** 손잡이를 끌면 가로·세로가 따로 논다. 사진은 `object-fit:cover` 라 찌그러지지는 않고 대신 **더 많이 잘린다**. 4:1 짜리 틀에 3:2 사진을 넣으면 위아래가 크게 날아간다. `cropped` 검사가 15% 이상 잘리면 잡지만, 역시 저장 후에야 안다.

**고침** Shift 를 누르고 끌면 원본 비율을 지키게 한다. 그리고 손잡이 옆에 지금 몇 % 가 잘리는지 작게 띄운다. 기본을 비율 고정으로 하고 Shift 로 푸는 쪽이 더 안전할 수도 있다 — 대부분은 잘리기를 원하지 않는다.
**품** 작음(20줄).

### 5. 글자 상자를 옮기면 뒤에 남는 자리가 그대로다

**무엇** 상자 옮기기는 `transform` 이라 **원래 자리는 그대로 비어 있다.** 제목을 아래로 내리면 위에 제목만 한 빈칸이 남는다.

**왜** PPT 를 생각하고 옮기면 결과가 예상과 다르다. 다만 이건 절충의 결과다 — `position:absolute` 로 바꾸면 레이아웃이 통째로 무너지고, 그 장의 나머지 배치가 다 어긋난다.

**고침** 두 갈래.
- (쉬움) 상자를 처음 옮길 때 "원래 자리는 비워 둡니다. 배치를 통째로 바꾸려면 슬라이드 유형을 바꾸세요" 를 한 번 띄운다.
- (제대로) `자유 배치` 토글을 만들어, 켜면 그 장의 모든 글자 상자를 현재 위치 그대로 `absolute` 로 굳힌다. 그다음부터는 PPT 처럼 움직인다. 대신 그 장은 반응형 배치를 포기하는 것이므로, 끄면 되돌아가게 원래 스타일을 기억해 둬야 한다.

**품** 쉬운 쪽 5줄 / 제대로 하는 쪽 60줄.

### 6. 표지 그라데이션의 방향과 폭이 고정이다

**무엇** 표지 배경 사진은 **항상 왼쪽으로** 사라진다. 글이 오른쪽에 있는 표지를 만들면 사진이 글 뒤에서 제일 진하다.

**고침** 사이드바에 방향 4개(왼쪽·오른쪽·위·아래)와 폭 슬라이더를 둔다. CSS 변수 `--fade-dir`, `--fade-at` 로 빼면 마스크 한 줄만 바꾸면 된다.
**품** 작음(25줄).

### 7. 자유 사진을 다른 장으로 옮길 수 없다

**무엇** 잘라내기·붙여넣기가 없다. 장을 잘못 골라 넣었으면 지우고 파일을 다시 골라야 한다. 검색으로 넣은 사진이면 출처까지 다시 받아야 한다.

**고침** 고른 자유 사진에 Ctrl+X / Ctrl+V 를 붙인다. 사진 데이터와 위치·크기·자르기·출처 열쇠를 한 덩어리로 들고 다니면 된다.
**품** 중간(40줄).

### 8. 사진 검색이 위키미디어 공용 하나뿐이다

**무엇** 위키미디어 공용은 백과사전용 사진이 많아 **발표 표지에 어울리는 사진이 잘 안 나온다.** 사용자가 원래 요청했던 Unsplash 류는 API 열쇠가 필요해서 단일 HTML 파일에 넣을 수 없었다.

**고침** 현실적인 대안은 두 가지다. (a) 검색어를 영어로 자동 변환해 결과를 늘린다 — 위키미디어는 한글 검색이 특히 약하다. (b) Openverse(열쇠 불필요, CC 전용)를 두 번째 출처로 붙이고 위키미디어와 결과를 섞는다. 예전에 이 컨테이너에서 Openverse 가 403 이었지만, **사용자 브라우저에서는 될 가능성이 높다** — 실패하면 조용히 위키미디어만 쓰게 하면 된다.
**품** 중간(40줄). (b)는 실제 브라우저에서 확인이 필요하다.

## 낮음 — 있으면 좋은 것

### 9. 슬라이드 목록에서 제목이 길면 사이드바를 밀어낸다
`white-space:normal / overflow:visible` 이라 제목이 길면 줄이 늘어난다. `text-overflow:ellipsis` + `nowrap` 한 줄이면 끝난다. **품 3줄.**

### 10. 편집기에 되돌리기 단축키만 있고 나머지가 없다
Ctrl+B(굵게), Ctrl+S(저장), Delete(고른 사진 지우기)가 없다. 사이드바를 매번 눌러야 한다. **품 15줄.**

### 11. 다크 테마에서 표지·마무리 색이 안 바뀐다
`--c-main`·`--c-sub` 는 다크에서 그대로 쓴다. 브랜드 색을 지키려는 의도지만, 아주 밝은 브랜드 색이면 다크 덱에서 표지만 눈부시게 튄다. 다크일 때 채도를 유지한 채 명도만 낮추는 선택지를 주면 된다. **품 20줄.**

### 12. 인쇄(PDF)에서 자유 사진의 그림자·모서리가 다르게 나온다
`@media print` 는 편집 표시만 지운다. 배경 그래픽을 끄고 인쇄하면 배경 사진과 막이 통째로 빠져 글자만 남는다. 인쇄 창에서 "배경 그래픽" 을 켜라는 안내가 RULES 에만 있고 화면에는 없다. PDF 저장 버튼 옆에 한 줄로 띄우면 된다. **품 5줄.**

### 13. `check.mjs` 가 저장된 파일만 볼 수 있다
편집 중에는 못 돌린다. 편집기 안에 "지금 검사" 버튼을 넣어 대비·넘침만이라도 브라우저에서 바로 돌리면, 저장→검사→다시 열기 왕복이 사라진다. 대비 계산 함수는 이미 편집기 안에 있다. **품 중간(60줄).**

## 손대지 않는 편이 낫다고 판단한 것

- **`.slide` 를 절대 배치로 바꾸는 것** — PPT 와 똑같아지지만, 창 크기가 달라져도 배치가 유지되는 이 도구의 가장 큰 장점을 버리게 된다. 자유 배치는 6번처럼 **장 단위 선택**으로 두는 게 맞다.
- **되돌리기를 명령 단위(diff)로 바꾸는 것** — 지금은 무대 전체를 찍는 단순한 방식이라 어떤 조작이든 빠짐없이 되돌아간다. diff 방식은 가볍지만, 새 기능을 만들 때마다 되돌리기도 같이 만들어야 해서 빠뜨리기 쉽다. 2번(사진 분리)만 해도 무게 문제는 해결된다.
- **자동 검사 항목을 더 늘리는 것** — 지금 7종이면 "확실히 틀린 것" 은 거의 덮는다. 더 늘리면 거짓 경보가 늘어 검사를 무시하게 된다. 남은 결함은 대부분 **눈으로 봐야 하는 것**이라, 항목을 늘리기보다 13번(편집 중 검사)과 AI 시각 검토를 쓰기 쉽게 만드는 쪽이 낫다.

## 내가 꼽는 우선순위

1. **1번(저장 안 하고 닫기)** — 유일하게 "한 일이 통째로 없어지는" 문제다.
2. **2번(스냅샷에서 사진 분리)** — 사진을 쓰는 사람에게 되돌리기가 사실상 없다.
3. **4번(비율 고정)** + **3번(밖으로 나감 경고)** — 둘 다 20줄 안쪽인데 체감이 크다.
4. **6번(그라데이션 방향)** — 표지는 가장 많이 손보는 장이다.
5. 나머지는 필요할 때.
