# 오디오 파일에 대사 이름 붙이기 — 사용 설명서

**스킬 이름**: `audio-rename-by-script`

이 문서는 프로그래밍을 몰라도 읽을 수 있게 썼습니다. 어려운 말이 나오면 바로 옆에 뜻을 적어뒀습니다.

---

## 1. 이 스킬은 무엇을 하나요

오디오 파일 수백 개가 이런 이름으로 있다고 해봅시다.

```
민서_1장_001.wav
민서_1장_002.wav
민서_1장_003.wav
...
```

이름만 봐서는 안에 무슨 대사가 들어 있는지 전혀 알 수 없습니다. 원하는 대사를 찾으려면 하나씩 열어서 들어봐야 합니다. 500개면 500번 들어야 합니다.

이 스킬은 그걸 이렇게 바꿔줍니다.

```
민서_1장_001_왜_그래.wav
민서_1장_002_나도_잘_모르겠어.wav
민서_1장_003_그럼_같이_가자.wav
...
```

이제 **파일 목록만 봐도 무슨 대사인지 바로 보입니다.** 검색창에 "같이 가자"를 치면 그 파일이 튀어나옵니다.

### 어디에 쓰나요

- 오디오북이나 오디오 드라마의 대사 파일 정리
- 성우 녹음본 정리
- 강의 녹음을 문장 단위로 잘라놓은 것 정리

한마디로 **"소리 파일이 많은데 뭐가 뭔지 모를 때"** 쓰는 도구입니다.

---

## 2. 어떻게 작동하나요 — 핵심 아이디어

여기가 이 스킬에서 가장 중요한 부분입니다. 이해하면 나머지는 다 쉽습니다.

### 그냥 받아쓰면 안 되나요?

컴퓨터가 소리를 글자로 바꿔주는 기술이 있습니다. **Whisper**(위스퍼)라고 부릅니다. OpenAI가 무료로 공개한 프로그램입니다.

그런데 Whisper는 완벽하지 않습니다. 특히 사람 이름을 자주 틀립니다.

```
실제 대사:  "김민서 씨, 오셨어요?"
Whisper:   "김민수 씨, 오셨어요?"   ← 이름을 틀렸다
```

이걸 그대로 파일 이름에 쓰면 **틀린 이름이 파일에 영원히 박힙니다.** 500개 파일에 조금씩 오타가 섞이면 나중에 검색도 안 되고 손댈 수도 없습니다.

### 그래서 원고를 씁니다

이 스킬의 핵심은 이겁니다.

> **Whisper가 들은 글자는 파일 이름에 쓰지 않는다.
> 원고에서 문장을 찾아내기 위한 "검색어"로만 쓰고 버린다.**

그림으로 보면 이렇습니다.

```
[오디오 파일]
      ↓ Whisper가 들음
   "김민수 씨"        ← 틀렸지만 상관없다
      ↓ 이걸로 원고를 검색
[원고 PDF] "김민서 씨, 오셨어요?"   ← 찾았다
      ↓ 원고 글자를 그대로 복사
[결과] 민서_1장_007_김민서_씨_오셨어요.wav   ← 정확하다
```

**Whisper는 "대충 이런 말이었어"라고 알려주는 역할만 합니다.** 실제로 파일 이름에 들어가는 글자는 원고에서 그대로 베껴옵니다. 원고는 사람이 쓴 정확한 글이니 오타가 있을 수 없습니다.

이게 이 스킬 전체를 관통하는 원칙입니다.

## 3. 준비물

### 넣어야 하는 것 두 가지

**첫째, 오디오 파일들**

이름이 `인물_챕터_순번` 형식이어야 합니다.

```
민서_1장_001.wav
민서_1장_002.wav
지훈_2장_001.wav
```

- **인물**: 누가 말하는지 (민서, 지훈, 내레이션 등)
- **챕터**: 몇 장인지 (1장, 2장, 프롤로그 등)
- **순번**: 그 챕터 안에서 몇 번째인지 (001, 002...)

**둘째, 원고 PDF**

오디오의 원본이 되는 글입니다. **글자를 복사할 수 있는 PDF**여야 합니다. 종이를 사진으로 찍은 PDF는 안 됩니다(컴퓨터 입장에서는 그냥 그림이라 글자를 읽을 수 없습니다).

> **확인 방법**: PDF를 열고 글자를 마우스로 드래그해보세요. 파란색으로 선택되면 OK, 아무 일도 안 일어나면 안 됩니다.

### 컴퓨터에 깔아야 하는 것

걱정 안 하셔도 됩니다. **스킬이 알아서 확인하고, 없으면 물어본 뒤 설치를 도와줍니다.**

| 프로그램 | 하는 일 | 용량 |
|---|---|---|
| 파이썬 | 작업을 실행하는 바탕 프로그램 | 작음 |
| ffmpeg | 소리 파일을 다루는 도구 | 작음 |
| Whisper (turbo) | 소리를 글자로 바꾸는 인공지능 | 약 1.6GB |
| Google Drive 앱 | 드라이브를 쓸 때만 필요 | 작음 |

전부 무료입니다. 총 3GB 정도의 여유 공간이 필요합니다.

**컴퓨터 사양**: 그래픽카드가 없는 평범한 노트북이면 충분합니다. 파일 하나에 몇 초 걸리는 정도입니다.

## 4. 사용 방법

### 쓰는 법은 아주 간단합니다

Claude에게 이렇게 말하면 됩니다.

> "오디오 폴더랑 원고 PDF 줄 테니까 파일 이름을 대사로 바꿔줘"

그리고 폴더 경로와 PDF 경로를 알려주면 됩니다. 나머지는 스킬이 순서대로 진행합니다.

### 진행되는 순서

**0단계 — 준비 확인**

- 컴퓨터가 윈도우인지 맥인지 **알아서 확인합니다.** 물어보지 않습니다.
- 필요한 프로그램이 깔려 있는지 표로 보여줍니다.
- 없는 게 있으면 **"설치할까요?"라고 물어본 뒤** 설치합니다. 마음대로 깔지 않습니다.
- 마지막에 파일 하나로 실제 테스트를 해봅니다. 이게 성공해야 다음으로 넘어갑니다.

**1~4단계 — 읽고 정리하기**

- 원고 PDF를 문장 단위로 자릅니다
- 원고에서 챕터가 어디서 시작하는지 찾습니다
- 오디오 파일 이름에서 인물·챕터·순번을 읽어냅니다
- 여기서 **"이 목록 맞나요?"라고 몇 번 확인을 요청합니다.** 귀찮아도 꼭 확인하세요. 여기가 틀리면 뒤가 전부 어긋납니다.

**5~6단계 — 듣고 짝 맞추기**

- Whisper가 오디오를 하나씩 들어서 글자로 바꿉니다
- 그 글자로 원고에서 같은 문장을 찾습니다
- 시간이 가장 오래 걸리는 부분입니다. 파일 500개면 몇십 분 걸릴 수 있습니다.

**7단계 — 미리보기 (중요)**

결과를 표로 먼저 보여줍니다.

| 원본 파일 | Whisper가 들은 것 | 원고에서 찾은 문장 | 새 이름 |
|---|---|---|---|
| 민서_1장_001.wav | 왜 그래요 | "왜 그래?" | 민서_1장_001_왜_그래.wav |

**여기서 승인하기 전까지는 아무 파일도 만들지 않습니다.** 이상한 게 보이면 이때 멈추면 됩니다.

**8~9단계 — 복사본 만들기**

승인하면 `renamed/`라는 새 폴더를 만들고 거기에 이름을 바꾼 **복사본**을 넣습니다.

---

## 5. 결과물은 이렇게 생겼습니다

```
오디오폴더/
├── (원본들 — 하나도 안 건드림)
└── renamed/
    ├── 민서_1장_001_왜_그래.wav
    ├── 민서_1장_002_나도_잘_모르겠어.wav
    ├── ...
    ├── unmatched/        ← 짝을 못 찾은 파일들
    ├── mapping.csv       ← 어떤 파일이 원고 어디인지 정리한 표
    └── report.md         ← 작업 결과 보고서
```

### mapping.csv에 들어 있는 것

엑셀로 열 수 있는 표입니다. 파일마다 이런 정보가 들어 있습니다.

- 원래 이름과 새 이름
- 인물, 챕터, 순번
- **원고 PDF 몇 쪽, 몇 번째 문장인지**
- 원고 문장 전체 (파일 이름은 40자로 잘리지만 여기엔 다 있습니다)
- Whisper가 뭐라고 들었는지

### report.md에 들어 있는 것

- 총 몇 개를 처리했고, 몇 개가 성공했는지
- 짝을 못 찾은 파일 목록과 그 이유
- 확신이 낮아서 사람이 확인해봐야 할 것들

## 6. 이 스킬에 특별히 넣은 기능들

그냥 만들면 안 되는 것들을 하나씩 막아뒀습니다.

### 원본은 절대 안 건드립니다

이름을 바꾸는 게 아니라 **복사본을 새로 만듭니다.** 결과가 마음에 안 들면 `renamed/` 폴더만 통째로 지우면 됩니다. 원본은 그대로입니다.

### 승인 없이는 아무것도 안 합니다

- 파일을 복사하기 전에 미리보기를 보여주고 물어봅니다
- 프로그램을 설치하기 전에 물어봅니다
- 구글 계정 로그인은 **사람이 직접** 합니다. 비밀번호를 대신 입력하지 않습니다

### 짧은 대사를 놓치지 않습니다

"네", "그래" 같은 짧은 대사는 한 글자만 틀려도 "완전히 다른 말"로 취급되기 쉽습니다.

> 시험에 비유하면: 문제 100개 중 1개 틀리면 99점이지만, 2개 중 1개 틀리면 50점입니다. 똑같이 하나 틀렸는데 점수가 딴판이죠.

그래서 이 스킬은 **"몇 퍼센트 닮았나"가 아니라 "몇 글자 틀렸나"로 판단합니다.** 짧은 문장은 1글자, 긴 문장은 여러 글자까지 봐줍니다.

### 반복되는 대사를 헷갈리지 않습니다

원고에 "네"가 50번 나온다고 해봅시다. 오디오의 "네"가 그중 어느 것인지 어떻게 알까요?

**순서를 따라갑니다.** 성우는 원고를 순서대로 읽었으니, 우리도 원고를 손가락으로 짚어가며 따라갑니다. 방금 120번 문장을 맞췄으면 다음 대사는 121번 근처에 있습니다. 멀리 있는 "네"는 후보에서 밀립니다.

여기에 **챕터 정보**까지 씁니다. 파일 이름이 `2장`이면 원고의 2장 범위 안에서만 찾습니다. 1장의 "네"를 잘못 집을 일이 아예 없어집니다.

### 순서가 어긋나면 알려줍니다

짝을 못 찾는 일이 세 번 연달아 생기면, 스킬이 "여기서부터 순서가 어긋난 것 같습니다"라고 보고서에 표시합니다. 조용히 틀린 채로 끝까지 가지 않습니다.

### 중간에 끊겨도 이어서 할 수 있습니다

작업 결과를 하나씩 바로바로 저장합니다. 컴퓨터가 꺼지거나 인터넷이 끊겨도 다시 실행하면 **하던 곳부터 이어서** 합니다. 처음부터 다시 하지 않습니다.

### 맥에서 한글 파일명이 깨지지 않게 합니다

맥은 한글을 자음·모음으로 쪼개서 저장하는 특이한 습관이 있습니다. 그냥 두면 `민서가_물었다`가 7글자가 아니라 16글자로 계산돼서 이름이 엉뚱한 데서 잘립니다. 이걸 미리 정리해둡니다.

### 구글 드라이브를 쓸 수 있습니다

드라이브에 오디오가 있어도 그대로 쓸 수 있습니다. 데스크톱용 Google Drive 앱을 깔면 드라이브가 컴퓨터의 폴더처럼 보이거든요. 그래서 **"다운로드"와 "업로드"라는 단계가 아예 없습니다.** 그 폴더에서 읽으면 다운로드고, 그 폴더에 쓰면 업로드입니다.

## 7. 주의사항

### 꼭 지켜야 할 것

**원고와 오디오의 순서가 같아야 합니다.**
파일 순번대로 나열했을 때 원고 순서와 같아야 합니다. 순서가 뒤죽박죽이면 짝을 못 맞춥니다.

**파일 이름 형식을 지켜야 합니다.**
`인물_챕터_순번` 형식이어야 합니다. 형식이 다른 파일은 스킬이 추측하지 않고 목록으로 보여준 뒤 물어봅니다.

**미리보기를 꼭 확인하세요.**
"확인 좀 해주세요"라고 할 때마다 대충 넘기지 마세요. 특히 원고 문장이 제대로 잘렸는지, 챕터 대응이 맞는지는 5분만 보면 됩니다. 여기서 놓치면 500개를 다시 해야 합니다.

### 구글 드라이브를 쓸 때 (아주 중요)

드라이브 앱은 기본이 **"스트리밍 모드"** 입니다. 폴더에 파일이 보여도 **실제 내용은 컴퓨터에 없고 클라우드에만 있습니다.** 열려고 할 때 그때그때 내려받습니다.

이 상태로 작업하면 이런 일이 생깁니다.

- 파일마다 다운로드를 기다려 몇 배로 느려짐
- 인터넷이 끊기면 중간에 실패
- 폴더는 멀쩡한데 파일을 못 읽는다는 오류

**해결책**: 오디오 폴더에서 오른쪽 클릭 → **"오프라인 사용 설정"**(Available offline)을 켜고, 다운로드가 다 끝날 때까지 기다리세요.

**용량도 확인하세요.** 결과물은 복사본이라 원본과 같은 용량을 한 번 더 씁니다. 오디오가 8GB면 8GB가 더 필요합니다. 무료 15GB를 쓰신다면 금방 찹니다.

**작업이 끝나면 바로 컴퓨터를 끄지 마세요.** 드라이브 앱 아이콘이 "동기화 완료"로 바뀔 때까지 기다려야 클라우드에 다 올라갑니다.

### 완벽하지 않은 부분

**짝을 못 찾는 파일이 나옵니다.** 보통 이런 이유입니다.

- 녹음할 때 대사가 바뀌었다
- 원고에 없는 NG 테이크나 안내 멘트가 섞였다
- 원고 PDF에서 문장이 이상하게 잘렸다

이런 파일은 `unmatched/` 폴더에 원래 이름 그대로 들어갑니다. 보고서를 보고 사람이 손보면 됩니다.

**보고서의 "낮은 확신" 목록은 꼭 보세요.** 짝은 찾았지만 확신이 부족한 것들입니다. 여기가 틀릴 가능성이 가장 높습니다.

### 저작권

시판 오디오북이나 남의 녹음본을 다룰 때는 조심하세요. 본인이 만든 것이나 권리가 있는 자료로 쓰는 게 안전합니다. 결과물을 배포할 계획이라면 미리 확인이 필요합니다.

## 8. 자주 묻는 질문

**Q. 인터넷이 필요한가요?**
처음 설치할 때만 필요합니다. Whisper 모델(1.6GB)을 한 번 내려받으면 그다음부터는 인터넷 없이도 돌아갑니다. 단, 구글 드라이브를 쓴다면 파일을 받아올 때 필요합니다.

**Q. 돈이 드나요?**
안 듭니다. Whisper는 MIT 라이선스라는 아주 느슨한 조건으로 무료 공개되어 있어서, 개인이든 회사든 자유롭게 쓸 수 있습니다.

**Q. 파일이 몇 개까지 되나요?**
개수 제한은 없습니다. 다만 많을수록 오래 걸립니다. 파일 하나에 몇 초씩이라고 보면 됩니다.

**Q. 영어 오디오도 되나요?**
지금은 한국어 전용으로 만들어져 있습니다. 언어 설정만 바꾸면 다른 언어도 가능하지만, 원고와 짝 맞추는 규칙(문장 자르기 등)은 한국어에 맞춰져 있습니다.

**Q. 파일 이름이 너무 길어지지 않나요?**
문장은 앞 40자까지만 넣습니다. 잘린 전체 문장은 mapping.csv에 다 남아 있습니다.

**Q. 실수로 잘못 실행하면요?**
원본을 안 건드리니 `renamed/` 폴더만 지우고 다시 하면 됩니다.

**Q. 대사가 "…" 하나뿐인 파일은요?**
부호만 있으면 이름을 만들 수 없습니다. 그래서 대신 위치를 넣습니다: `민서_1장_003_원고12쪽34번.wav`. 파일 목록만 봐도 원고 어디인지 알 수 있습니다.

## 10. 한 장 요약

```
[준비]  오디오 파일(인물_챕터_순번) + 원고 PDF
            ↓
[0단계] 컴퓨터 확인하고 필요한 프로그램 설치 (물어보고)
            ↓
[1-4]   원고를 문장으로 자르고, 파일 이름에서 정보 읽기
            ↓
[5-6]   Whisper가 듣고 → 원고에서 같은 문장 찾기
            ↓
[7단계] 미리보기 보여주고 승인 받기  ← 여기서 확인!
            ↓
[8-9]   복사본 만들기 (원본은 그대로)
            ↓
[결과]  민서_1장_001_왜_그래.wav + mapping.csv + report.md
```

**기억할 것 세 가지**

1. 파일 이름의 글자는 **원고에서 그대로 베껴옵니다.** Whisper가 틀려도 이름은 정확합니다.
2. **원본은 절대 안 건드립니다.** 항상 복사본을 만듭니다.
3. **"확인해주세요"라고 할 때 꼭 확인하세요.** 5분 아끼려다 500개를 다시 하게 됩니다.
